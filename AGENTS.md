# Repository workflow

After completing and verifying requested changes in this repository, commit the files in scope and push the working branch to `origin`. Open or reuse a pull request targeting the repository's current default branch whenever possible. Report the push and PR link, or the specific blocker if either step fails.

# Planning documents (文書 1〜8)

When the user says 「文書 N をやって」 (or "do document N"), read `docs/plan-roadmap.md` first. It lists what each document covers, the decisions already made with the user, and how to write it (format, `docs/agent-tiers.md` for the per-step model/effort tier, checking current behaviour in the engine before writing). Write the instructions only, not code, then update the status table in that file.
