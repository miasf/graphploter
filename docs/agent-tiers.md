# 担当の段階（モデルと effort の目安）

指示書の各ステップには「担当: A」のように**段階だけ**を書く。段階とモデルの対応は、この表だけで管理する
（モデルが替わったら、ここだけ直す。指示書は直さない）。最終更新: 2026-11-25。

## 1. 段階

| 段階 | 向いている仕事 | 例 |
|---|---|---|
| **A** | 正しさに落とし穴が多い新しいアルゴリズム。間違えても見た目では気づきにくいもの | 媒介変数の消去と除く所、リーマン面の枝のつなぎ方、経路の近くの特異点、摂動法の深い拡大 |
| **B** | 今ある仕組みに乗せる中くらいの機能。画面と計算エンジンの両方を触るもの | 新しい記法と描き方、⚙ の項目、残像、サンプルの仕組み |
| **C** | 正解が決まっている定型の仕事 | テストの表（物差し）、定型の関数、README、サンプルの追加 |
| **P** | 指示書（計画）を書く仕事 | `docs/plan-*.md` を書く・直す |

## 2. 対応表

| 段階 | Claude（第 1 候補） | Claude（上位が使えないとき） | ChatGPT・Gemini など |
|---|---|---|---|
| **P** | Fable 5.2・high（設計の迷いが大きい章だけ xhigh） | Opus 5.5・xhigh | その時点の最上位の推論モデル・推論の強さを最大 |
| **A** | Opus 5.5・xhigh（設計を詰め直すステップは Fable 5.2・high） | Opus 5.5・high ＋ 下の「下げるときの決まり」 | 最上位の推論モデル・推論の強さを最大か高 |
| **B** | Opus 5.5・high | Sonnet 5.5・high | 上位の推論モデル・推論の強さを中〜高 |
| **C** | Sonnet 5.5・medium | Haiku 5.5・high | 標準のモデル |

ChatGPT・Gemini の欄は、会社ごとに推論の強さの目盛りが違うので、目安。モデル名は書かない（すぐ古くなり、正確な名前を保証できない）。

## 3. 下げるときの決まり

段階 A のステップを、表の第 1 候補より下のモデルでやるときは、そのまま渡さず、次の 3 つを必ずする:

1. **完了の条件のテストを先に書かせ、通らないことを確かめてから実装させる**
2. ステップを、テストが 1 つずつ通る単位にさらに分ける（1 PR は小さく）
3. PR の説明に「段階 A を下位のモデルで実装した」と書き、レビューを段階 A のモデル（または人）に頼む

## 4. ほかの会社のエージェントに渡すとき

- 作業の決まりは `AGENTS.md`（どの会社のツールも読む）。Claude 専用の機能（スキル・サブエージェント）には頼らない
- 準備: Rust（stable）と `wasm-pack`、Node.js（`web/` で `npm ci`）。テストは `core/` で `cargo test --release`、`web/` で `npm test`
- 指示書の 0 章「進み具合」の表に、状態と「計画との違い」を書く（誰が実装しても記録の形を同じにする）
