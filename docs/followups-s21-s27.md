# S21〜S27 の残りの課題（やり直し用）

計画 `docs/plan-hard-tasks.md` の 7 章（S17〜S27）を、計画の順番（S22 → S21 → S25 → S24 → S26 → S27 → S23）で一通り実装した後に残った課題。
S20 の分は `docs/s20-followups.md` にある。全ステップ共通の決まり（7.3 の後の箇条書き）は同じく守る。

数字は `shape_report`（7.1 と同じ設定: $x, y \in [-10, 10]$、$z \in [-6.4, 6.4]$、陽関数の細かさ 150・陰関数 80、$128^3$ 箱）。
「前」はそのステップの直前のコミット、「後」はそのステップの後。

## 1. S22（陰関数: 定義域の縁・破片）

- **破片を消すと本物の面も消える**（優先度: 高）。`mod(x y, z) = 1` の面は、格子より細かく詰まった本物の面のかけら。
  破片とみなす大きさ（三角形 12 個以下）を 2・4 個にしても両方の条件は満たせなかった。計画の 7.4 の 19 のとおり、
  1,000 個より多く消したら `kind` に「（細かすぎて描けない部分あり）」と出している。S27（細かい格子）で救う前提だった所
- **`1/(x y) - z`（混ぜた回転）**: 破片 135 → 1 だが、欠け 14 → 22%（極に張り付く壁のかけらも消すため）。S23 の後は 0%
- **縁の高さ**: 半球の縁は垂直なので、Surface Nets の角の丸まりで $z \approx 0.33$ で切れる。見た目の差はわずか（半球からは 0.01）。
  直すなら、縁の上の点を、縁に沿って $F = 0$ の所まで動かす処理が要る
- **`sqrt(x)+sqrt(y)+sqrt(z)=3` の xy 回転**: 欠け 0.08 → 1.6%。原因は調べていない
- **埋めた値の平均**: 縁で値が暴れる式（計画 7.4 の 15）は試していない

## 2. S21（陽関数: 格子より細い山・谷）

- 計画どおりの 8 × 8 マスのブロック・$\tau$ の係数 0.5 では、ブロックの別の所で格子の点が尾根の頂上近くに乗ると、ブロック全体の値の範囲が広くなり、
  `3 exp(-400 (y - sin(x))^2)` の $x = \pm 9.5$ を見落とした。最初の箱を「ブロックが 8,000 個ほどまで」の大きさ（細かさ 150 なら 2 × 2 マス）、係数 0.1 にした。
  区間演算の回数（細かさ 150 で約 5,600 回 + 掘り下げ）と時間を、細かさ 300 以上でも確かめる
- 遅くなった式: `gamma(x)/5 + y/5` 141 → 214 ms、xw の `3 sin(1/x)` 27 → 139 ms（どちらも種が多い）

## 3. S25（陽関数: 細い極の線）

- **三角形の数**（優先度: 中）: 計画は「極の細分が予算を使い切っている」と見立てたが、今の版では極は切り分けで描けていて、
  `nCr(x, y)` の細分の半分は「表示範囲の上端・下端を横切る急な斜面」、残りは範囲の中の急な所。極の周りではない。
  細分（`refine_keep`）が上限 9 万個に、S20 の細分が上限 2 万個に張り付いている。上限の決め方か、表示範囲の端を横切る所の細分の
  やり方（端の高さの所を二分で直接求める `clip_to_height_range` があるので、細分は要らないかもしれない）を見直す
- **段差探しの追加の二分**: 差の大きい段差（高さの範囲の 0.3 倍超）を、さらに 18 回二分して極のすぐそばまで狭めるようにした（計画には無い）。
  これで `nPr(x, y)/10` の $x = -8$ が 56 → 74/80、`gamma` の $x = -8$ が 0 → 80/80 になった
- **悪くなった数字**: `nPr(x, y)/10`・`nCr(x, y)/nCr(y, x)` の余計が 7〜24% 増えた（壁が上下の端まで届くようになった分。
  `gamma` と同じく、正解の側が細い極を捉えられていない疑い。余計の箱の位置を確かめる）。xw の `3 sin(1/x)` の欠け 0 → 2.1%、
  回した `1/(sin(x) + cos(y))` の余計 0 → 2〜3%（追加の二分が、極でない急な所の切り位置をずらした疑い）
- 重い式（格子の計算が 3 ms 以上）では、中点を 4 辺に 1 辺だけ計算する（計画どおり）。これが `nCr` の時間の増加のほとんど

## 4. S24（媒介変数の曲面の段差）

- `cut_by_jumps` の切り出しで陽関数の結果が変わらないことは、壁あり・3 辺とも飛ぶ式・極の式の 7 つで、頂点と三角形のハッシュが前とまったく同じことで確かめた。
  常設のテストにするなら、切り出す前の版の結果を固定値として持つ必要がある（以後の変更で必ず変わるので、やっていない）
- 表示範囲の対角線は `tol × 1000` から求めている（`lib.rs` が `tol = size × 10⁻³` を渡す前提）。引数で渡すほうがよい
- 複素平面の図形で効いていることは確かめていない

## 5. S26（陰関数の段差を枝ごとに）

- **`floor(x y) = z floor(z)` が悪くなった**（優先度: 高）: 欠け 14.6 → 約 43%。この式は $0 \le z < 1$、$0 \le xy < 1$ で $F \equiv 0$（立体の零点）を持ち、
  その境目（$F$ が 0 から飛ぶ所）が「面」として数えられる。枝ごとの面と同じセルにそういう境目があると、ふつうの Surface Nets から外した分が欠ける。
  「どの枝の $F_\tau$ にも頂点が置かれないセルは、ふつうの Surface Nets に任せる」までは入れた
- **枝の上限**: 1 つのセルに出てよい枝を 2 種類にした（計画は 4）。4 だと `mod(x y z, 4) = 2` が欠け 2.7 → 20.6% に悪くなる（枝が細かく変わる所で、
  切り取った小さな面が破片として消える疑い）。2 だと `mod(x y, z) = 1` が 4.0 → 7.1%
- **時間**: 段差の多い式で 3〜8 倍（`mod(x y, z) = z/2` 724 → 約 2,500 ms、`mod(x, 2) + mod(y, 2) + mod(z, 2) = 2` 133 → 約 1,000 ms、
  細かさ 200 では数秒〜数十秒）。調べるセル（符号の混ざるセルとその面の隣）が多く、枝ごとに $F_\tau$ を計算するため。
  $F_\tau$ を計算する点の数そのものが $F$ と同じくらいあるので、2 倍以内にするのは難しい。枝ごとの小さな Surface Nets を、ハッシュ表でなく配列で持つなどで縮める余地はある
- 混ぜた回転の `z = mod(x y, z)` の余計が 0.1 → 4.7%（境目にちょうど乗る面の切れ端）
- 範囲で重ねた立体・再生中は、この道を使わない（計画どおり）

## 6. S27（陰関数を必要な所だけ細かく）

- **段差・極・定義域の縁・接する所・近い曲面のある式では行わない**（優先度: 中）。細かくした版は格子全体を作り直すので、
  本体のそれらの処理（S1・S4・S22・S26・近い曲面を分ける）と両立しない。計画の「(b) 埋めた角・零点でない辺・段差をまたぐセルを含むブロックも選ぶ」はやっていない。
  なので `mod(z, x y) = 1` などには効かない
- **2 段だけ**: 4 倍の段は作っていない。円錐の先は 0.204 → 0.102（条件は 0.05）
- 選ぶのは法線が 35° を超えてずれる所だけ（計画の (c)「S10 があきらめた成分」はやっていない）
- 作り直したメッシュの「近い曲面を分ける」は無い（1 つのセルに頂点 1 つ）。近い曲面のある式では行わないので問題は出ないはず

## 7. S23（陰関数: 極に張り付く面）

- **時間**: `tan(x) - z = 0` が約 7.7 倍（極の平面に沿って、同じ符号の辺 10 万本を 32 等分して調べる）。極の隣の薄い零点は辺の 1/16 ほどの幅しかないので、
  点を減らすと見落とす。極の位置（零点でない辺の二分の結果）から、極を含みそうな辺だけを選ぶ工夫が要る
- xy・xz の回転の `tan(x) = z y` が欠け 16%・7%（回転なしは 0.7%）。極の面が格子に対して斜めになると、極と零点が 1 本の辺に入らない所が増える疑い
- 計画の 4（1 つのセルで極の両側に零点があるとき頂点を分ける）はやっていない。そういうセルでは頂点が 1 つにまとまり、極をまたぐ三角形になる可能性がある
  （`implicit_pole_is_not_a_surface` は通っている）
