# 陰関数を「部品に分けて」描く（練り直しの方針と、今の状態）

S22〜S27 の陰関数の改善は、格子の上の値から「ここは接しているらしい」「ここで飛んでいるらしい」と**推測**して継ぎはぎする
やり方だった。粗い格子（回転の再生中）や、1 つのセルに面が何枚も通る所で崩れる（穴・破片・裏返り・上下の非対称）。
練り直しでは、**式そのものを変形**して、符号がふつうに変わるなめらかな面の集まりにしてから描く。

- 式の変形: `core/src/eval/pieces.rs`
- 部品ごとに描いて、条件で切り取る: `core/src/mesh/pieces.rs`（入口は `implicit_solid_opt`）
- 見た目の確かめ: `tools/visual`（回転・再生中の設定の式も入れた）

## 入ったもの

### 1. 因数に分ける
$A B = 0$ は $A = 0$ と $B = 0$。$A^n = 0$（$n > 0$）・$|A| = 0$・$\sqrt{A} = 0$・$A/B = 0$ は $A = 0$。
`(x^2+y^2-4)^2 (z-1)^2 = 0` は、円柱と平面を別々の、ふつうの陰関数として描く（前は「0 に触れるだけの面」を探していた）。
因数の零点のうち、元の式が定義されない所（ほかの因数が定義されない所）は切り落とす。

### 2. 段差の枝に分ける
`floor`・`ceil`・`round`・`sign`・`mod` のある因数は、枝の番号の組 $\tau$ ごとに

$$F = 0 \iff \bigcup_\tau \{ F_\tau = 0 \ \text{かつ}\ \text{枝}\ \tau\ \text{にいる} \}$$

と分ける。$F_\tau$ は段差の元を定数に置き換えたなめらかな式（`mod(a, b)` → $a - \tau b$）で、さらに因数に分ける
（`mod(x y, z) = 0` の $\tau = 0$ は $xy = 0$ → 平面 $x = 0$ と $y = 0$）。
「枝にいる」は、段差の元の引数 $s$ の範囲（`floor` なら $\tau \le s < \tau + 1$）。面を作ってから、範囲の外を切り落とす。

- **境目が面に重なるとき**: `mod(x y, z) = 0` の面 $xy = \tau z$ は、枝の境目 $xy/z = \tau$ そのもの。頂点を面の上にニュートン法で寄せてから
  条件を調べ、ほとんどの頂点が同じ端の上なら「面が境目に重なっている」とみなして、端を含む枝（`floor` の下の端）なら全部描き、
  含まない枝（`z = mod(x y, z)` の上の端）なら全部捨てる
- **描く枝**: 格子点の多い順。格子より薄い枝（$z = 0$ の近くに無限に重なる層）は描き分けられないので描かず、
  説明に「（細かすぎて描けない部分あり）」と出す。薄いかどうかは、枝の格子点のうち「どの軸でも隣が同じ枝」の点が 3 割より少ないかで決める
- **速さ**: 枝ごとに、その枝の格子点があるブロックだけで面を作る（`BLOCK_MASK`）

### 3. 極を通分して消す（成績表の B）
$F = N/D$ の形に直して（`Program::rationalized`）、分子 $N = 0$ を描く。$F = 0 \iff N = 0$ かつ $D \ne 0$ で、$N$ には極
（符号は変わるが零点でない所）が無いので、「極の平面に面を張るか」を格子の値から推測しなくてよい。

- 変形: `tan` → $\sin/\cos$、`cot` → $\cos/\sin$、`sec`・`csc` → $1/\cos$・$1/\sin$。割り算と負のべきは分母へ、和・差は通分。
  それ以外の関数は、引数の中に割り算があっても 1 つの項のまま（`sin(1/x)` は変えない）
- `tan(x) = z y` は $\sin x - z y \cos x = 0$、`1/(x y) - z = 0` は $1 - x y z = 0$ になる
- **通分しない式**: 分子と分母が同時に 0 になる式（`sin(x)/x - z`。$x = 0$ は極ではなく、なめらかにつながる）は、通分すると
  $N = \sin x - x z$ に余計な平面 $x = 0$ ができる。粗い格子（32 等分）の辺のうち $D$ の符号が変わる辺の上で $D = 0$ の点を二分で求め、
  そこで $N \ne 0$ の辺（本当の極）が 2 割より少なければ、通分せずに今までの道で描く（`poles_worth_removing`）
- 通分した面のうち $D = 0$ の所（本当の極と、取り除ける特異点が混ざった式）は、頂点を面の上に寄せてから切り落とす（`clip_piece` の `nonzero`）

| 式 | 前（余計な面。細かさ 80 / 再生中 40 / 24） | 後 | 時間（細かさ 80） |
|---|---|---|---|
| `tan(x) = z y` | 20.2% / 16.3% / 10.8% | どれも 0% | 341 → 89 ms（回したもの 832 → 96 ms）|
| `1/(x y) - z = 0` | 0%（S23 の推測で描けていた） | 0% | 223 → 17 ms |

ほかの 30 式は変わらない。テスト: `eval::pieces::tests::rationalized_removes_poles`、
`mesh::pieces::tests::poles_are_removed_by_clearing_denominators`（$z = \tan(x)/y$ の上の点と比べる。`sin(x)/x - z` に余計な面が無い）。

### 4. 部品の多い式を速くした（下の旧 6）
部品が 800 個前後ある式（`mod(x,2)+mod(y,2)+mod(z,2)=2`・`floor(x)+floor(y)+z = mod(x y, 3)`）の時間を測ると、部品 1 つあたりの手間が
ほぼ全部だった。原因と、直したこと:

- **枝よりずっと広い範囲で面を作っていた**: 部品の格子は「枝のある 8 マス単位のブロックと、その隣」の範囲だったので、
  小さい枝（1 辺 2 の箱）では、必要な範囲の 8〜80 倍のマスで面を作ってから切り落としていた（切り取りで調べる頂点も数倍）。
  → 枝ごとに格子点のある範囲（`BranchGroup::lo`・`hi`）を持ち、その 1 マス外までに絞る（`piece_grid`）
- **面の通らない部品**: 絞った範囲のブロックを区間演算で調べ、面が無ければ作らない（`prune_mask`）
- **切り取りで頂点を面に寄せる計算**: 勾配を差分で求めていた（1 回につき式の計算 7 回）のを、メッシュの法線の向きに寄せる（2 回）
- **枝の式の組み立て**: 同じ命令をまとめるのに、命令を文字列に直して比べていた。数値のキーに替えた（`eval::OpKey`。ふつうの式のコンパイルも速くなる）

| 式 | 細かさ 80 | 再生中 40 | 再生中 24 |
|---|---|---|---|
| `mod(x,2)+mod(y,2)+mod(z,2)=2` | 558 → 210 ms | 365 → 186 ms | 177 → 104 ms |
| 同（回す） | 1,038 → 397 ms | 438 → 221 ms | 342 → 240 ms |
| `floor(x)+floor(y)+z = mod(x y, 3)` | 844 → 303 ms | 716 → 261 ms | 332 → 225 ms |
| 同（回す） | 1,470 → 737 ms | 944 → 548 ms | 608 → 337 ms |

（1 回ずつの計測で、同じ式でも 2 割ほどぶれる。）32 式の合計は、細かさ 80 が 15.5 → 11.2 秒、再生中 40 が 6.1 → 4.3 秒、再生中 24 が 3.5 → 2.7 秒。
形は変わらない（欠け・余計の平均の差は 0.1 ポイント以内。`docs/audit/2026-11-12-poles-speed.tsv`）。

**残っている手間**（再生中 40 の `floor(x)+floor(y)+z = mod(x y, 3)` で）: 枝を調べる下準備が 40〜60 ms（細かさ 80 の格子で調べるので、
面を粗くしても減らない）、面作りが 170 ms 前後、切り取りが 45 ms 前後。面作りは、縦に細長い枝（1×1×12 の柱）を面が 1 か所で横切るだけなのに、
柱を囲む立方体の格子（1 辺 43 点）を部品ごとに用意していることによる。区間演算では柱の中の面の高さを絞れなかった
（$x y$ の幅が広すぎる）ので、枝の条件（$3k \le x y < 3k + 3$）を使って絞るか、立方体でない格子を作れるようにする必要がある。
試して効かなかったもの: 式の計算の作業用の配列の使い回し（実時間は変わらない）、面のある所だけへの格子の縮め直し。
→ 面作りは、枝の条件を使って絞った（下の「5」）。

### 5. 部品の範囲を、枝の条件で絞った（「4」の残りの面作り）
縦に細長い枝（1×1×12 の柱）を面が 1 か所で横切るだけの部品でも、柱を囲む立方体の格子を用意していた。枝を固定した式
$F_\tau$ をそのまま区間演算にかけても、$x y$ の幅が広くて面の高さを絞れない。そこで **枝の条件を区間演算に渡す**:
`mod(a, b)` の枝 $\tau$ では、余り $a - \tau b$ は $0$ と $b$ の間にあるので、余りをその範囲の独立な変数に置き換えた式
（`Program::frozen_relaxed`）で調べる。`floor(x)+floor(y)+z = mod(x y, 3)` の枝 $(a, b, k)$ は $a + b + z - [0, 3]$ になり、
$z$ が $-a-b$ 〜 $3-a-b$ の外の層には面が無いと分かる。

- 部品の格子（`piece_grid`）で、面が無いと分かるマスの層を、軸ごとに両端から外す（面のあるマスの 2 マス外までは残す）。
  どの層にも面が無い枝は作らない
- **描く範囲を減らさない**: 今までは、枝の格子点の無い所でも、ブロック（8 マス単位）の区切りの都合で面を作る範囲に入っていれば、
  そこにある枝の細い切れ端の面が描けていた（`mod(x y, z) = 1` の $z = 1$〜$2$ で、面積の 2 割ほど）。層を外すと区切りがずれて
  これが消えるので、ブロックの印は外す前の区切りで付けてから新しい格子に直し、外す前に面を作っていた範囲（立方体のうち、
  枝の範囲にかかるブロックまで）から層を外す。層を外さなかった部品は、格子も印も前と同じ

| 式 | 細かさ 80 | 再生中 40 | 再生中 24 | 80（回す） | 再生中 40（回す） | 再生中 24（回す） |
|---|---|---|---|---|---|---|
| `floor(x)+floor(y)+z = mod(x y, 3)` | 459 → 188 ms | 345 → 160 | 271 → 141 | 769 → 309 | 695 → 338 | 389 → 220 |
| `mod(x y, z) = 1` | 510 → 322 | 194 → 137 | 103 → 118 | 659 → 508 | 234 → 192 | 125 → 117 |
| `mod(x^2 + y^2, z) = 1` | 500 → 271 | 181 → 132 | 112 → 92 | 564 → 342 | 222 → 151 | 126 → 113 |
| `mod(x + y, z) = 0.5` | 200 → 125 | 72 → 57 | 44 → 41 | 363 → 237 | 104 → 99 | 65 → 62 |

（1 回ずつの計測で、2 割ほどぶれる。）32 式の合計は、細かさ 80 が 12.9 → 11.2 秒、再生中 40 が 5.1 → 4.3 秒、再生中 24 が 3.1 → 2.8 秒。
`mod(x,2)+mod(y,2)+mod(z,2)=2` は変わらない（枝が 1 辺 2 の箱で、外せる層が無い）。

**形が変わらないことの確かめ**（`tools/visual/cases.tsv` の 118 式で、つぶれていない三角形の集合を前後で比べた）:
114 式は完全に同じ。違うのは、`mod(x^2 + y^2, z) = 1`（34 万個のうち 288 個）と `floor(x)+floor(y)+z = mod(x y, 3)`（4.9 万個のうち 324 個）で、
同じ面の三角形の切り方が変わっただけ（面積の差は 0.001 以下。細い部分を 2 倍の細かさで作り直すブロックの区切りがずれたため）。
`min(x y, z) = mod(x, 2)` は、表示範囲の外（描画で切り落とす所）の三角形が 232 個減った（範囲の中は同じ）。
残りの 1 式は陽関数で、この変更とは関係なく結果がぶれる式（下の「陰関数ではないが、比べていて分かったこと」）。画像の比較でも、変化は 0.0%。
成績表の回した版では、`floor(x)+floor(y)+z = mod(x y, 3)` の面が 0.2〜0.4% 増えた（増えた三角形は全部、元の式の面の上）。
欠け・余計が 0.1 ポイントより悪くなった行は無い（`docs/audit/2026-11-12-clip-trim.tsv`）。
テスト: `mesh::pieces::tests::tall_branches_keep_their_faces`（面を式から直接求めて比べる）、`eval::pieces::tests::branch_conds_of_mod_and_floor`。

**残っている手間**: 枝を調べる下準備（40〜60 ms。細かさ 80 の格子で調べるので、面を粗くしても減らない）と、切り取り。
面作りは、立方体でない格子を作れるようにすれば、さらに減る（今は、いちばん長い軸に合わせた立方体）。

### 6. 切り取りでできる、つぶれた三角形を無くした（成績表の C の正体）
成績表の「裏返り」（`mod(x,2)+mod(y,2)+mod(z,2)=2` で 4〜5%、`min(x y, z) = mod(x, 2)` で 4〜9%）を調べると、面の向きは
そろっていて、原因は **面積 0 の三角形** だった。回していない式では、枝の境目が格子の面に重なるので、切り取りの境目が
頂点そのものになり、3 頂点が同じ位置の三角形が大量にできていた（`mod(x,2)+mod(y,2)+mod(z,2)=2` で 15.4 万個のうち 1.1 万個）。
境目が頂点から辺の長さの $10^{-4}$ 倍より近ければ、頂点を足さずにその頂点を使い、同じ頂点を 2 回使う三角形は入れない（`CUT_SNAP`）。

| 式（回さない） | 裏返り %（80 / 再生中 40 / 24） | 三角形（細かさ 80） |
|---|---|---|
| `mod(x,2)+mod(y,2)+mod(z,2)=2` | 3.9 / 5.3 / 4.5 → どれも 0.0 | 153,698 → 142,456 |
| `min(x y, z) = mod(x, 2)` | 5.4 / 8.9 / 4.0 → 1.2 / 1.1 / 0.7 | 37,001 → 34,047 |

32 式の裏返りの平均は、細かさ 80 が 0.38 → 0.11%、再生中 40 が 0.62 → 0.18%、再生中 24 が 0.58 → 0.30%。見た目は変わらない
（消したのは面積 0 の三角形だけ。118 式で、つぶれていない三角形の集合が前後で同じ）。
残りの裏返り（`mod(x y, z) = 0` の再生中 24 で 4.4%）は、面が本当に枝分かれする所（何枚もの面が $z$ 軸の上の 1 本の辺に集まる）で、向きの乱れではない。
テスト: `mesh::pieces::tests::clipping_leaves_no_collapsed_triangles`。

### 7. 面の両側のセルで、つながり方の判断がそろうようにした（ジャイロイドの穴）
回転中・再生中のジャイロイドに穴が開いていた（前の版でこれを「粗さによる向きのずれ」と見誤り、直す所が無いと書いたのは誤り。
裏返りだけを見て、縁の辺を見ていなかった）。視点を回している間に描く粗い版では、三角形 1.1 万個のうち縁の辺が 105〜119 本あり、
向こうが透けて見えていた。細かさ 80 の本体にも、1 マス分の小さな穴が 22 個あった。

原因は 2 つ:

- **面のあいまいさ**: ジャイロイドは $x = \pm 7\pi/4$ などで格子の平面にほぼ重なり、その平面の上の格子点で $F$ の符号が市松に入れ替わる。
  1 つのセルを 2 枚の曲面が通るとき、少ないほうの符号の角を辺のつながりだけで組に分けていたので、面を共有する 2 つのセルで
  少ないほうの符号が逆だと、両側とも「相手の符号の対角がつながる」とみなし、その面の上に四角形が張られなかった。
  → 共通の関数 `corner_groups` にまとめ、隣のセルの少ないほうの符号が逆のときは、面の上の双一次補間の鞍点の値
  $s = \frac{ab - cd}{(a + b) - (c + d)}$ の符号でどちらの対角がつながるかを決める（両側が同じ値を計算するので、判断がそろう）。
  同じときは前と同じく切る（両側ともつなぐと、セルより細い管が 1 本の辺につぶれて、3 つ以上の三角形が集まる辺になる。
  最初は常に鞍点の値で決めたが、`sin(x) sin(y) sin(z) = 0.001` でそういう辺が 2,604 本できたので、こうした）。
  本体・粗い版と作り直し（`nets_on_grid`）・テスト用の写し（`implicit_solid_reference`）の 3 か所とも同じ規則にした
- **極の見誤り**: 面が辺にほぼ沿っていて両端の値がとても小さい辺（$2.4 \times 10^{-5}$ と $-6.2 \times 10^{-4}$）が、
  二分 6 回で値が半分まで縮まず「極」とされ、面が張られなかった（`false_crossings`）。→ 縮まなかった辺だけ、二分を 18 回続けて決め直す

| 式 | 穴の縁の辺（前 → 後） |
|---|---|
| ジャイロイド（細かさ 80 / 回して 80 / 再生中 40 / 24） | 88 / 16 / 24 / 128 → どれも 0 |
| ジャイロイドの粗い版（視点を回している間） | 105〜119 → 0 |
| `sin(x) sin(y) sin(z) = 0.001` | 1,456 → 0（粗い版 646 → 0） |
| `sin(40/(x^2+y^2+z^2+1)) = 0.5` | 1,400 → 0 |

ほかの式は変わらない（118 式のうち、この 4 式と、三角形 10 個分が変わった `floor(x)+floor(y)+z = mod(x y, 3)`、関係なくぶれる陽関数 1 式のほかは、
三角形の集合が前後で同じ）。成績表で欠け・余計が悪くなった行は無い。3 つ以上の三角形が集まる辺は、`sin(40/…)` で 80 → 24 本に減り、
`sin(x) sin(y) sin(z) = 0.001` の粗い版に 16 本できた（前はそこに穴の縁が 646 本）。破片は `sin(40/…)` の細かさ 80 で 26 → 30 個。
テスト: `mesh::tests::gyroid_has_no_holes`（細かさ 80・40・24 と粗い版で、表示範囲の内側に縁の辺が無い）。

`mesh::pieces::tests::coarse_gyroid_is_not_flipped`（前の版で足した）は、向きがそろっていることだけを確かめる。

### 8. 薄い枝でも、枝の中を面が通るなら描く（細かさ 80 と 160 の差）
成績表のいちばん悪い行（細かさ 160 と比べた欠け: `floor(x y) = z floor(z)` 72%、`mod(x y z, 4) = 2` 59%、`mod(x^2 + y^2, z) = 1` 45%）を、
正解の分かる `floor(x y) = z floor(z)` で調べた。面は、高さ $z = i/k$ の水平な帯 $i \le xy < i + 1$（$k^2 \le i < k^2 + k$）。
本当の面の上の点と比べると、細かさ 80 は **82%**、基準の細かさ 160 も **46%** が欠けていた（成績表の「差」は、欠けの一部しか表していなかった）。
原因は 2 つ:

- **薄い枝の規則**: 枝の領域が格子より薄い所は「面が格子より細かく重なって描き分けられない」として描いていなかった。
  薄いかどうかは「どの軸の向きにも隣が同じ枝の点か」で決めていたので、横（$x$・$y$）にだけ薄く、面に垂直な向き（$z$）には厚い帯も
  描かなかった。→ 薄くても、枝の中で隣り合う 2 つの格子点（両方その枝で、表示範囲の中）の間で $F$ の符号が変わる所があれば描く
  （面に垂直な向きに薄い層では、同じ枝の隣の点がそもそも無いので、ここを通らない）。ただし、同じ枝の描くブロックが隣（26 方向）に
  無い、ぽつんと 1 つのブロックは描かない
- **切り取りが細い帯を見落とす**: 切り取りは頂点ごとに条件を調べるので、帯が三角形より細いと、帯の中に頂点の無い三角形は丸ごと
  捨てられていた。→ 条件の範囲をまたぐ三角形（ある頂点で下の端より下、別の頂点で上の端より上）を、辺の中点で 3 回まで分ける
  （`split_straddling`。辺ごとに分けるので、隣の三角形と頂点を共有し、隙間はできない）

描き方: 前から描いていたブロックのある枝は、新しいブロックも同じ部品に入れ、前と同じ細かさで描く（部品の格子の線は全体の格子と同じなので、
前から描いていた所の面は変わらない）。新しいブロックしか無い枝は、その後で、別の見積もり（`TARGET_EXTRA_TRIANGLES`）で細かさを決め、
三角形 30 万個（`MAX_EXTRA_TRIANGLES`）で打ち切る。同じ枝を 2 つの部品に分けると、ブロックの境目のあたりで同じ面を 2 回描く
（成績表の「裏返り」が再生中 24 で 13% になった）ので、分けない。

|---|---|

`floor(x y) = z floor(z)` の帯の真ん中の線の上の点のうち、描けている割合は、細かさ 80 で 9% → 82%、再生中 24 で 4% → 82%。
`mod(x y z, 4) = 2`・`mod(x^2 + y^2, z) = 1` は、ブロック単位でぎざぎざに欠けていた縁が、なめらかにつながった（画像で確かめた）。

**代償**（正しさを優先すると決めて入れた）: 面を多く描くので、`mod` の多い式が重くなる。成績表の 32 式の合計時間は、細かさ 80 で +47%、

### 9. 回転だけが変わったときは、回す前の形を作って回す（`mesh::LocalMesh`）
回転が表示中の座標どうしだけなら、回転は形を変えずに動かすだけ。今までは回転のたびに、回した式で表示範囲の格子に作り直していた
（再生中は細かさ 24〜40 に落として毎コマ）。回した陽関数と同じく、回転の中心から表示範囲の角までの距離 $\rho$ の立方体で、
回す前の式 $F$ のメッシュを 1 回作り、頂点と法線に回転を掛けて描く（はみ出た所は描画側で切り落とす）。切り口のふたは、
表示中の座標 $q$ を回す前の座標 $p = R^\top(q - c) + c$ に移して $F$ を計算する（`Field::mapped`）。

- **使う条件**: 回転だけが変わった依頼（`plotClient.ts` の `markRotationOnly` が flags のビット 3 を付ける）で、段差（`floor`・`mod` など）の
  無い式。広い範囲は作るのが数倍遅いので、スライダー・式が変わったときは今までの道。段差のある式は、薄い枝を描かない判定が範囲全体で
  決まるため、広い範囲で作ると表示範囲の中の枝まで消える（`mod(x y z, 4) = 2` で 6 割欠けた）ので使わない
- **格子の間隔**: 表示範囲の一番狭い座標（既定では z）に合わせる（細かさは 2 倍まで）。一番広い座標に合わせると、
  `x^2 y^2 + y^2 z^2 + z^2 x^2 = 1` の細い腕が 14% 欠けた
- **Worker**: 覚えた形は、再生・ドラッグ中なら細かさが違っても回すだけで使う。止まったら、細かさが同じ形が無ければ作り直す。
  回すだけで描けるときは、F の計算を Worker に分けない

結果（成績表の回した版。段差の無い式。基準は今までの道の細かさ 160。テスト: `core/tests/rotated_implicit.rs`）:

| 再生中 40 | 8.9 → 4.9 | 1.7 → 6.0 | 162 → 181 |

  そろうので、斜めの格子（基準も）が描けずにいた細い帯まで描けている
- 欠けの減った分は `x^2 y^2 + y^2 z^2 + z^2 x^2 = 1`（再生中 24 で 19.6 → 0%）など

### 10. 格子より薄い枝のうち、1 次の部品だけの枝を陽関数として描く（陰関数定理）
枝の部品 $F_\tau$ がある座標 $v$ について 1 次（$F_\tau = a v + b$。`Program::solved_for`）で、枝の範囲で $a$ が 0 にならない
（区間演算で確かめる）なら、陰関数定理の条件 $\partial F_\tau/\partial v = a \ne 0$ が範囲全体で成り立ち、範囲の中の面は
$v = -b/a$ の 1 枚の陽関数。格子の細かさによらず描ける（`thin_graph`）。

- **使う枝**: 今まで描いていなかった枝（どのブロックも薄くて外した枝）だけ。格子で描ける所のある枝まで陽関数にすると、
  三角形の上限（陽関数の分は 40 万）に先に届き、細かさ 200 で今まで描けていた所が欠けた。今の形では、今まで描いていた面は変わらず、足すだけ
- **速さ**: 枝ごとに、陽関数の変数 2 つの平面のうち、その枝のブロックのある列だけを、まず 4 マスずつの粗い格子で、次に枝があるかもしれない
  粗いマス（と隣）だけを細かい格子で調べる。面が枝に含まれない境目に重なる枝（`z = mod(x y, z)`）は粗い格子の段階で捨てる。
  頂点はもう面の上にあるので、切り取りで面に寄せない。枝の条件の式の極（`x y / z` の $z = 0$）をまたぐ三角形は分けない（`POLE_SPAN`）
- **切れ端**: 枝の境目で切った面の、三角形 12 個以下の成分は捨てる（今までは枝ごと描いていなかった所）。切り取りで、成り立たない側の頂点の
  すぐ手前に境目があるときは、その頂点の位置に 1 つだけ頂点を足して共有する（ほぼ同じ位置の 2 点でつぶれた三角形ができないように）

- **係数が 0 になる所のある部品**: 1 次でも、範囲の中で係数 $a$ が 0 になるかもしれない部品（`mod(x y z, 4) = 2` の枝 $xyz - 4\tau - 2$ は
  $z$ について 1 次で、$a = xy$ が $x = 0$・$y = 0$ で 0）は、格子のマスごとに 4 つの角の $a$ の符号がそろうマスだけを描く
  （箱ごとに陰関数定理の条件を確かめる形の、いちばん簡単な版）。範囲全体で $a \ne 0$ と確かめられる座標があれば、そちらを先に使う。
  `mod(x y z, 4) = 2` の欠けが 18.61 → **1.11%**（細かさ 80。710 → 894 ms。三角形の上限 150 万に届く）。回した版と細かさ 200 は変わらない

結果（`tests/shape.rs` の正解と比べた欠け。回さない）:

| 式 | 細かさ 80 | 細かさ 200 | 時間（細かさ 80） |
|---|---|---|---|
| `mod(x y, z) = 1` | 4.13 → **0.00%** | 0.00 → 0.00% | 558 → 742 ms |
| `mod(x^2 + y^2, z) = 1` | 9.76 → **2.04%** | 0.71 → **0.00%** | 711 → 926 ms |
| `mod(x y, z) = z/2` | 19.65 → 19.65% | 6.48 → **4.26%** | 928 → 968 ms |

どの式も欠けは増えず、破片も増えない。成績表（`tools/visual/audit.py`）では、回さない版の欠けの平均が 1.69 → 0.81%、裏返りが 0.20 → 0.05%。

### 11. 法線を式の勾配から求める（再生・ドラッグ中に陰影が変わって見えるのを抑える）
再生やスライダーを動かし始めると、1 コマの持ち時間に収めるため格子を粗くして作り直す（細かさ 80 → 20〜28）。法線を周りの三角形の
向きの平均で求めていたので、粗い面では法線が本当の面の向きから数度〜十数度ずれ、動き始めと止まったときに光の当たり方が変わって見えた。
頂点の法線を式の勾配 $\nabla F$（前進差分。刻みはマスの $10^{-3}$）の向きにする（`gradient_normals`）。勾配が有限でない・ほとんど 0・
三角形の向きの平均と 70° 以上違う頂点（特異点・折れ目・極の近く）は、今までどおり三角形の平均。

| 式 | 本当の面の向きとのずれ（細かさ 24、平均 / 95%） |
|---|---|
| ジャイロイド | 5.6° / 12.2° → 0.0° / 0.0° |
| Schwarz P | 5.2° / 11.3° → 0.0° / 0.0° |
| トーラス | 3.4° / 7.3° → 0.0° / 0.0° |

八面体のような折れ目のある面は、粗い面でも角がにじまず、面が平らに描ける。止まったときの計算は 1〜2 割遅くなる（ジャイロイドで 88 → 107 ms）。
テスト: `core/tests/rotated_implicit.rs` の `normal_report`（無視するテスト。数字を出す）

## 全体を測る物差し（成績表）

個別の式を見て直すと、見た式だけが良くなる。`tools/visual/audit.py` は、全部の陰関数（32 式）を同じ物差しで測る:
細かさ 160 を基準に、細かさ 80・回転の再生中の軽い計算（細かさ 40・24）を、回さないものと回したもので比べ、
欠け・余計・裏返り・破片を出す。結果は `docs/audit/` に残す。直す所は、この表の悪い行を**原因の種類ごと**にまとめて決める。

### 1 回目の表で分かったこと（`docs/audit/2026-11-12-before.tsv`）と、直したこと

段差も極も無いふつうの陰関数は、どの版でも欠け・余計がほぼ 0。悪い行は次の種類に分かれた。

- **A. 描く枝が、面を作る格子の細かさで変わる**（`mod`・`floor` のある 12 式のほぼ全部）: 再生中に粗くすると面が 30〜100% 消え、
  細かさ 160 では三角形の上限に当たって面が減っていた。→ 直した:
  - どの枝を描くかは、表示範囲を 80 等分した格子（`ENUM_N`。面を作る格子がそれより細かければその格子）で決める。面を作る格子の細かさでは変えない
  - 「薄くて描き分けられない」は、枝まるごとではなく**ブロックごと**に決める（一部だけ混み合う面は、描ける所だけ描く）
  - 三角形が増えすぎる式は、面の数を減らすのではなく、枝の部品を作る格子を粗くする（`TARGET_PIECE_TRIANGLES`）
  - 枝の部品は、その枝がある範囲だけの小さな格子（全体の格子の一部。`piece_grid`）で作る
- **B. 極の推測**（`tan(x) = z y`）: 細かさによって余計な面が 10〜20%。→ 直した（下の「3. 極を通分して消す」）
- C. 面の向きが部品ごとにばらばら（裏返り 5〜10%）に見えたもの。→ 調べると、向きではなく、切り取りでできる面積 0 の三角形だった。
  直した（上の「6. 切り取りでできる、つぶれた三角形を無くした」）
- D. 格子より細い形（`x^2 y^2 + y^2 z^2 + z^2 x^2 = 1` を回して粗くしたときの細い管）

| 版 | 欠け %（前 → 後） | 余計 %（前 → 後） |
|---|---|---|
| 80 | 4.44 → 6.76 | 3.34 → 0.73 |
| 再生中 40 | 14.39 → 3.95 | 0.51 → 0.69 |
| 再生中 24 | 18.15 → 2.43 | 0.34 → 0.34 |
| 80（回す） | 4.39 → 7.44 | 2.62 → 0.34 |
| 再生中 40（回す） | 13.87 → 4.44 | 0.10 → 0.10 |
| 再生中 24（回す） | 16.24 → 3.12 | 0.02 → 0.02 |

（32 式の平均。）細かさ 80 の欠けが増えたのは、前は基準（細かさ 160）のほうが三角形の上限で面を落としていたため。
今の「80 と 160 の差」は、細かい格子ほど、重なった面を多く描き分けられることによる（`mod(x y z, 4) = 2`・`mod(x^2 + y^2, z) = 1`・
`floor(x y) = z floor(z)` で大きい）。

## まだのもの（次にやる順）

1. **定義域の縁**（`sqrt`・`ln`）: S22 の「埋めてから切る」のまま。成績表の 3 式（`sqrt(x)+sqrt(y)+sqrt(z)=3`・`ln(x)+ln(y)+ln(z)=1`・
   `sqrt(36-x^2-y^2)-z=0`）は、どの版も欠け・余計が 0〜1.2% で、見た目にも崩れは無い。急がない。やるなら、$\sqrt{g}$ を $g < 0$ へ
   奇関数としてつなげた式（$\operatorname{sign}(g)\sqrt{|g|}$。どこでも定義される）で面を作り、$g \ge 0$ の条件で切り取る
   （段差の枝と同じ `clip_piece` が使える。`ln(g)` は $\ln|g|$）
2. **三角形の数**: `mod(x y, z) = 0` は 89 万個（描き分けられる面を全部描くため）。スマホで重ければ、面ごとの細かさを下げる
3. **古い道の整理**: S26（`branch_meshes`）は、枝の組が 2 万を超える式でしか通らない。`tools/visual/cases.tsv` の 118 式では 1 回も通らない

   陰関数 40 式の全部で呼ばれている（因数に分けられない式 `max(…)^2` などのために、どの式でも候補を探す）ので、消せない
4. **部品の多い式の残りの時間**: 上の「5」の「残っている手間」。立方体でない格子と、枝を調べる下準備
5. **細かさ 80 と 160 の差**: 上の「8」で大きく縮めた。残りは、`floor(x y) = z floor(z)` の帯の 2 割（帯が途切れる所）と、
   面が格子とほぼ同じ間隔で重なる密な層（`mod(x y, z) = 1` の細かさ 80 で 15%）。重くなった `mod` の式の時間を減らすのが次の課題

6. **1 次の部品を陽関数として描く**: 下の「10」で、今まで描いていなかった薄い枝だけに入れた。厚い所と薄い所が混ざる枝（`mod(x y, z) = z/2` は細かさ 80 で 20% 欠けたまま）と、1 次でない部品（陰関数定理の条件 $\partial F/\partial v \ne 0$ を箱ごとに区間演算で確かめてニュートン法で解く）が残り。
   厚い所と薄い所が混ざる枝で、薄いので外したブロックの所だけを陽関数で描く（格子で描いたブロックの中の三角形は捨てる）版も試したが、

   三角形の上限（150 万）に届いていて変わらず、細かさ 200 では薄い枝の上限の取り合いで 4.3 → 6.5% に増えた。格子で描いた所との
   継ぎ目に破片もできた（継ぎ目の頂点を共有しないと消えない）。`z/2` を直すには、三角形の上限の中で何を描くかの決め方から変える必要がある
7. **回す前の形を、段差のある式でも使う**: 薄い枝の判定を表示範囲の中だけで決めるようにすれば使える（上の「9」）

### 陰関数ではないが、比べていて分かったこと
- 陽関数で区間演算が使えない式（`(x^2+y^2)^(1/3) sin(4 arg(x + i y))` など）は、最初の格子の計算が 3 ms 以上かかると追加の探索を
  省く（`hidden_features`・`trace_poles` の `base_ms`）。計算時間が 3 ms の前後の式では、マシンの混み具合で結果が変わる
  （同じ式で三角形が 45,664 個のときと 45,568 個のときがある）。見た目の比較で「変わった」と出ても、描画の変更のせいとは限らない
