# 陰関数を「部品に分けて」描く（練り直しの方針と、今の状態）

S22〜S27 の陰関数の改善は、格子の上の値から「ここは接しているらしい」「ここで飛んでいるらしい」と**推測**して継ぎはぎする
やり方だった。粗い格子（回転の再生中）や、1 つのセルに面が何枚も通る所で崩れる（穴・破片・裏返り・上下の非対称）。
練り直しでは、**式そのものを変形**して、符号がふつうに変わるなめらかな面の集まりにしてから描く。

- 式の変形: `core/src/eval/pieces.rs`
- 部品ごとに描いて、条件で切り取る: `core/src/mesh/pieces.rs`（入口は `implicit_solid_opt`）
- 見た目の確かめ: `tools/visual`（回転・再生中の設定の式も入れた）

## 入ったもの

### 1. 因数に分ける
$A B = 0$ は $A = 0$ と $B = 0$。$A^n = 0$（$n > 0$）・$|A| = 0$・$\sqrt{A} = 0$・$A/B = 0$ は $A = 0$。
`(x^2+y^2-4)^2 (z-1)^2 = 0` は、円柱と平面を別々の、ふつうの陰関数として描く（前は「0 に触れるだけの面」を探していた）。
因数の零点のうち、元の式が定義されない所（ほかの因数が定義されない所）は切り落とす。

### 2. 段差の枝に分ける
`floor`・`ceil`・`round`・`sign`・`mod` のある因数は、枝の番号の組 $\tau$ ごとに

$$F = 0 \iff \bigcup_\tau \{ F_\tau = 0 \ \text{かつ}\ \text{枝}\ \tau\ \text{にいる} \}$$

と分ける。$F_\tau$ は段差の元を定数に置き換えたなめらかな式（`mod(a, b)` → $a - \tau b$）で、さらに因数に分ける
（`mod(x y, z) = 0` の $\tau = 0$ は $xy = 0$ → 平面 $x = 0$ と $y = 0$）。
「枝にいる」は、段差の元の引数 $s$ の範囲（`floor` なら $\tau \le s < \tau + 1$）。面を作ってから、範囲の外を切り落とす。

- **境目が面に重なるとき**: `mod(x y, z) = 0` の面 $xy = \tau z$ は、枝の境目 $xy/z = \tau$ そのもの。頂点を面の上にニュートン法で寄せてから
  条件を調べ、ほとんどの頂点が同じ端の上なら「面が境目に重なっている」とみなして、端を含む枝（`floor` の下の端）なら全部描き、
  含まない枝（`z = mod(x y, z)` の上の端）なら全部捨てる
- **描く枝**: 格子点の多い順。格子より薄い枝（$z = 0$ の近くに無限に重なる層）は描き分けられないので描かず、
  説明に「（細かすぎて描けない部分あり）」と出す。薄いかどうかは、枝の格子点のうち「どの軸でも隣が同じ枝」の点が 3 割より少ないかで決める
- **速さ**: 枝ごとに、その枝の格子点があるブロックだけで面を作る（`BLOCK_MASK`）

### 3. 極を通分して消す（成績表の B）
$F = N/D$ の形に直して（`Program::rationalized`）、分子 $N = 0$ を描く。$F = 0 \iff N = 0$ かつ $D \ne 0$ で、$N$ には極
（符号は変わるが零点でない所）が無いので、「極の平面に面を張るか」を格子の値から推測しなくてよい。

- 変形: `tan` → $\sin/\cos$、`cot` → $\cos/\sin$、`sec`・`csc` → $1/\cos$・$1/\sin$。割り算と負のべきは分母へ、和・差は通分。
  それ以外の関数は、引数の中に割り算があっても 1 つの項のまま（`sin(1/x)` は変えない）
- `tan(x) = z y` は $\sin x - z y \cos x = 0$、`1/(x y) - z = 0` は $1 - x y z = 0$ になる
- **通分しない式**: 分子と分母が同時に 0 になる式（`sin(x)/x - z`。$x = 0$ は極ではなく、なめらかにつながる）は、通分すると
  $N = \sin x - x z$ に余計な平面 $x = 0$ ができる。粗い格子（32 等分）の辺のうち $D$ の符号が変わる辺の上で $D = 0$ の点を二分で求め、
  そこで $N \ne 0$ の辺（本当の極）が 2 割より少なければ、通分せずに今までの道で描く（`poles_worth_removing`）
- 通分した面のうち $D = 0$ の所（本当の極と、取り除ける特異点が混ざった式）は、頂点を面の上に寄せてから切り落とす（`clip_piece` の `nonzero`）

| 式 | 前（余計な面。細かさ 80 / 再生中 40 / 24） | 後 | 時間（細かさ 80） |
|---|---|---|---|
| `tan(x) = z y` | 20.2% / 16.3% / 10.8% | どれも 0% | 341 → 89 ms（回したもの 832 → 96 ms）|
| `1/(x y) - z = 0` | 0%（S23 の推測で描けていた） | 0% | 223 → 17 ms |

ほかの 30 式は変わらない。テスト: `eval::pieces::tests::rationalized_removes_poles`、
`mesh::pieces::tests::poles_are_removed_by_clearing_denominators`（$z = \tan(x)/y$ の上の点と比べる。`sin(x)/x - z` に余計な面が無い）。

### 4. 部品の多い式を速くした（下の旧 6）
部品が 800 個前後ある式（`mod(x,2)+mod(y,2)+mod(z,2)=2`・`floor(x)+floor(y)+z = mod(x y, 3)`）の時間を測ると、部品 1 つあたりの手間が
ほぼ全部だった。原因と、直したこと:

- **枝よりずっと広い範囲で面を作っていた**: 部品の格子は「枝のある 8 マス単位のブロックと、その隣」の範囲だったので、
  小さい枝（1 辺 2 の箱）では、必要な範囲の 8〜80 倍のマスで面を作ってから切り落としていた（切り取りで調べる頂点も数倍）。
  → 枝ごとに格子点のある範囲（`BranchGroup::lo`・`hi`）を持ち、その 1 マス外までに絞る（`piece_grid`）
- **面の通らない部品**: 絞った範囲のブロックを区間演算で調べ、面が無ければ作らない（`prune_mask`）
- **切り取りで頂点を面に寄せる計算**: 勾配を差分で求めていた（1 回につき式の計算 7 回）のを、メッシュの法線の向きに寄せる（2 回）
- **枝の式の組み立て**: 同じ命令をまとめるのに、命令を文字列に直して比べていた。数値のキーに替えた（`eval::OpKey`。ふつうの式のコンパイルも速くなる）

| 式 | 細かさ 80 | 再生中 40 | 再生中 24 |
|---|---|---|---|
| `mod(x,2)+mod(y,2)+mod(z,2)=2` | 558 → 210 ms | 365 → 186 ms | 177 → 104 ms |
| 同（回す） | 1,038 → 397 ms | 438 → 221 ms | 342 → 240 ms |
| `floor(x)+floor(y)+z = mod(x y, 3)` | 844 → 303 ms | 716 → 261 ms | 332 → 225 ms |
| 同（回す） | 1,470 → 737 ms | 944 → 548 ms | 608 → 337 ms |

（1 回ずつの計測で、同じ式でも 2 割ほどぶれる。）32 式の合計は、細かさ 80 が 15.5 → 11.2 秒、再生中 40 が 6.1 → 4.3 秒、再生中 24 が 3.5 → 2.7 秒。
形は変わらない（欠け・余計の平均の差は 0.1 ポイント以内。`docs/audit/2026-11-12-poles-speed.tsv`）。

**残っている手間**（再生中 40 の `floor(x)+floor(y)+z = mod(x y, 3)` で）: 枝を調べる下準備が 40〜60 ms（細かさ 80 の格子で調べるので、
面を粗くしても減らない）、面作りが 170 ms 前後、切り取りが 45 ms 前後。面作りは、縦に細長い枝（1×1×12 の柱）を面が 1 か所で横切るだけなのに、
柱を囲む立方体の格子（1 辺 43 点）を部品ごとに用意していることによる。区間演算では柱の中の面の高さを絞れなかった
（$x y$ の幅が広すぎる）ので、枝の条件（$3k \le x y < 3k + 3$）を使って絞るか、立方体でない格子を作れるようにする必要がある。
試して効かなかったもの: 式の計算の作業用の配列の使い回し（実時間は変わらない）、面のある所だけへの格子の縮め直し。

## 全体を測る物差し（成績表）

個別の式を見て直すと、見た式だけが良くなる。`tools/visual/audit.py` は、全部の陰関数（32 式）を同じ物差しで測る:
細かさ 160 を基準に、細かさ 80・回転の再生中の軽い計算（細かさ 40・24）を、回さないものと回したもので比べ、
欠け・余計・裏返り・破片を出す。結果は `docs/audit/` に残す。直す所は、この表の悪い行を**原因の種類ごと**にまとめて決める。

### 1 回目の表で分かったこと（`docs/audit/2026-11-12-before.tsv`）と、直したこと

段差も極も無いふつうの陰関数は、どの版でも欠け・余計がほぼ 0。悪い行は次の種類に分かれた。

- **A. 描く枝が、面を作る格子の細かさで変わる**（`mod`・`floor` のある 12 式のほぼ全部）: 再生中に粗くすると面が 30〜100% 消え、
  細かさ 160 では三角形の上限に当たって面が減っていた。→ 直した:
  - どの枝を描くかは、表示範囲を 80 等分した格子（`ENUM_N`。面を作る格子がそれより細かければその格子）で決める。面を作る格子の細かさでは変えない
  - 「薄くて描き分けられない」は、枝まるごとではなく**ブロックごと**に決める（一部だけ混み合う面は、描ける所だけ描く）
  - 三角形が増えすぎる式は、面の数を減らすのではなく、枝の部品を作る格子を粗くする（`TARGET_PIECE_TRIANGLES`）
  - 枝の部品は、その枝がある範囲だけの小さな格子（全体の格子の一部。`piece_grid`）で作る
- **B. 極の推測**（`tan(x) = z y`）: 細かさによって余計な面が 10〜20%。→ 直した（下の「3. 極を通分して消す」）
- C. 面の向きが部品ごとにばらばら（裏返り 5〜10%。両面を同じ色で描くので、見た目への影響は小さい）
- D. 格子より細い形（`x^2 y^2 + y^2 z^2 + z^2 x^2 = 1` を回して粗くしたときの細い管）

| 版 | 欠け %（前 → 後） | 余計 %（前 → 後） |
|---|---|---|
| 80 | 4.44 → 6.76 | 3.34 → 0.73 |
| 再生中 40 | 14.39 → 3.95 | 0.51 → 0.69 |
| 再生中 24 | 18.15 → 2.43 | 0.34 → 0.34 |
| 80（回す） | 4.39 → 7.44 | 2.62 → 0.34 |
| 再生中 40（回す） | 13.87 → 4.44 | 0.10 → 0.10 |
| 再生中 24（回す） | 16.24 → 3.12 | 0.02 → 0.02 |

（32 式の平均。）細かさ 80 の欠けが増えたのは、前は基準（細かさ 160）のほうが三角形の上限で面を落としていたため。
今の「80 と 160 の差」は、細かい格子ほど、重なった面を多く描き分けられることによる（`mod(x y z, 4) = 2`・`mod(x^2 + y^2, z) = 1`・
`floor(x y) = z floor(z)` で大きい）。

### この物差しの限界
基準も同じプログラムで作るので、どの細かさでも同じように間違える所は見つからない。正解が式から分かるものは、テスト（`mesh::pieces::tests`）で確かめる。

## まだのもの（次にやる順）

1. **再生中のジャイロイド**（細かさ 24）に、裏返った小片が出る。因数も段差も無いふつうの面なので、Surface Nets の本体（近い曲面を分ける処理か、
   軽い作り直し）の問題。`tools/visual` の `r_gy_play24`
2. **定義域の縁**（`sqrt`・`ln`）: S22 の「埋めてから切る」のまま。$\sqrt{g}$ を含む式を、$g \ge 0$ の条件つきの部品にできるか調べる
3. **三角形の数**: `mod(x y, z) = 0` は 100 万個（描き分けられる 34 枚の面を全部描くため）。スマホで重ければ、面ごとの細かさを下げる
4. **古い道の整理**: S26（`branch_meshes`）は、枝の組が 2 万を超える式でしか通らなくなった。0 に触れる面の探索（`touch_search`）も、
   因数に分けられない式（`max(…)^2` など）でだけ要る。安定を確かめてから消す
5. **部品の多い式の残りの時間**: 上の「4. 部品の多い式を速くした」の「残っている手間」。細長い枝の格子と、枝を調べる下準備
