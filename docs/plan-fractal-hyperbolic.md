# 計画: フラクタル・深い拡大・双曲幾何

文書 3（`docs/plan-roadmap.md`）。式から描くフラクタル（脱出時間・ニュートン法）、フラクタルを作りやすくする道具（L システム・IFS・用意した例・3D・次元）、
深い拡大（摂動法と、ふつうのグラフの相対座標 N9）、双曲幾何（ポアンカレ円板・メビウス変換・敷き詰め・アポロニウスのガスケット）を、
1 ステップずつ（1 ステップ = 1 PR）の指示書にする。ステップの名前は、式から描くフラクタルが **F0〜F3**、作りやすくする道具が **I0〜I4**、
深い拡大が **K0〜K4**、双曲幾何が **Y0〜Y3**。
各ステップの「担当」は `docs/agent-tiers.md` の段階。各ステップの「実装の土台」は、関数の形・データの形・処理の流れの下書き。
**土台は出発点で、命令ではない**。コードを読んで合わない所があれば直してよく、そのときは 0 章の表に「計画との違い」を書く。

**この文書の芯**: フラクタルは「点ごとに同じ計算を何百回もくり返す」ので、今の式の道（式を展開して 1 つの長い式にする・メッシュを作る）には乗らない。

- くり返しは**くり返しのまま** GPU の画素ごとの計算にする（12 章の G 系と同じ「Rust の基準の実装 → GLSL に移して画素ごとに突き合わせる」の決まり）
- 点・線で描くもの（L システム・IFS・アポロニウス・測地線）は、今の点と線の道（`Plot::Points`）に乗せる
- 深い拡大は、f64 では足りない所（幅 $10^{-13}$ より細かい所）だけ、高い精度の 1 本の軌道と、そこからの差（摂動）で描く

### 1.2 計算エンジンで確かめた今の動き

`core/tests/` に一時的なテストを置き、`plot`（2D は `flat = true`）と `equation::compile` で確かめた（終わったので消した）。
規則は `definitions` に `z_(n+1)=z_(n)^2+x+i*y`、初項は `z0 = 0` のスライダーとして渡した（画面のサンプルと同じ形）。

**漸化式で書いたマンデルブロ集合**（2D、表示範囲 $[-2, 1] \times [-1.5, 1.5]$、細かさ 80）

| 式 | 結果 | 時間 |
|---|---|---|
| $\lvert z_{10}\rvert = 2$・$\lvert z_{20}\rvert = 2$ | 陰関数の曲線（メッシュ）。**GPU の描き方に乗らない**（「複素数を使う式は GPU の描き方では使えません」） | 4.4・5.4 ms |
| $\lvert z_{50}\rvert = 2$ | 頂点 6 個だけ（ほとんど消える。$z_n$ があふれて $\infty$・NaN になる所は零点を探せない） | 9.8 ms |
| $\lvert z_{100}\rvert = 2$ | 頂点 0 個（何も出ない） | 22.6 ms |
| $\lvert z_{19}\rvert < 2$〜$\lvert z_{40}\rvert < 2$ | 不等式の領域（2D）で頂点 0 個（何も出ない。細かさ 200 でも同じ） | 7〜15 ms |
| $\lvert z_{300}\rvert < 2$ | 頂点 5,931 個（あふれた所の境目だけが残る） | 132 ms |
| $\lvert z_{1000}\rvert < 2$ | **計算エンジンのスタックがあふれてテストのプロセスごと落ちた**（項の式を再帰で展開するため） | — |
| 3D の `z = z_(20)`（複素数の色分け）・`z = abs(z_(20))` | 陽関数として描ける | 360〜375 ms |

- 初項に座標を書けない: `w_0 = x + iy`（ニュートン法の図・ジュリア集合の始点）を定義の行に書いても初項にならない（「変数 'w1' はここでは使えません（初項 w_1 を定義してください）」）
- `f^{(3)}(z)` は**累乗** $f(z)^3$（$f(z) = z^2 - 0.75$ で $f^{(3)}(0) = -0.421875 = (-0.75)^3$）。合成のくり返し $f \circ f \circ f$ は `(f∘f∘f)(…)` と書けば描けるが、回数を数で書く方法は無い
- 実数の 2 本の漸化式で書いたマンデルブロ集合（`a_(n+1)=a_(n)^2-b_(n)^2+x`・`b_(n+1)=2*a_(n)*b_(n)+y`、$a_{20}^2 + b_{20}^2 = 4$）は、**1.3 秒かかって描けなかった**（展開した式が大きくなる）
- 点群 `@orbitpoints(a_0,b_0,8192)`（エノン写像）: 81 ms。分岐図 `@bifurcation(F,0.2,2.5,4)`: 6,409 点・2 ms

**画素ごとの CPU の計算の速さの目安**（ネイティブ。WASM はこの 1.5〜2 倍）: $z^2 + c$ を $800 \times 600$ 画素・最大 256 回（合計 2,285 万回）で 80 ms（1 回 3.5 ns）。
命令列（`Program`）の解釈で同じことをすると、上の $\lvert z_{20}\rvert = 2$ の時間から 1 回 40 ns ほど（同じ画素数で 1 秒ほど）。**CPU は基準の実装と予備の道にし、画面は GPU で描く**

**深い拡大**（2D、`y = (x - 1000000)^2`、表示範囲の幅 $10^{-3}$、中心 $x = 10^6$）: 頂点の横の座標が f32 で全部 `1000000.0` になり、曲線が縦の線につぶれる（N9 の問題）。
エンジンの計算（f64）は正しく、頂点を f32 にする所で失う

## 2. 全体の決めごと

### 2.1 描き方は 3 つの道のどれかに乗せる

| 道 | 使うもの | 出力 | 書き出し・カーソルの下の点 |
|---|---|---|---|
| **画素ごと（2D の GPU）** | 脱出時間（F2）・ニュートン法（F3）・敷き詰めの塗り（Y1）・深い拡大（K3） | 計算エンジンが GLSL を作り、画面の材質が画素ごとに計算して塗る | 画素の値（反復の回数・どの根か）を、Worker の CPU の基準の実装で 1 点だけ計算して出す |
| **点と線** | L システム（I0）・IFS（I1）・測地線と多角形（Y0）・敷き詰めの辺（Y1）・アポロニウス（Y2） | `Plot::Points`（線は NaN で切る） | 今と同じ |
| **3D の距離の見積もり（GPU の光線）** | メンガーのスポンジ・マンデルバルブ（I3） | 用意した GLSL（式からは作らない） | Worker で 1 本の光線を CPU で計算 |

### 2.2 計算エンジンは「数」を返し、色は画面が付ける

脱出時間は、画素ごとに**なめらかにした反復の回数** $\nu$（実数。脱出しなければ $-1$）を作り、色はそこから画面のシェーダーが付ける。
色の周期・ずれ・内側の色を変えても、計算し直さない（uniform を変えるだけ）。$\nu$ の式（$d$ は写像の次数、$R$ は脱出半径、$n$ は $\lvert z_n\rvert > R$ になった最初の回数）:

$$\nu = n + 1 - \log_d\!\left(\frac{\ln\lvert z_n\rvert}{\ln R}\right)$$

次数 $d$ は、計算エンジンが $\lvert Z\rvert = 10^6$ の 8 点で $\dfrac{\ln\lvert f(Z)\rvert}{\ln\lvert Z\rvert}$ を求め、8 点が $10^{-3}$ 以内でそろい、整数に $10^{-2}$ 以内なら、その整数。
そろわなければ（$e^z + c$ など）$d = 0$ とし、画面は $\nu = n$（整数の回数）で塗る。

### 2.3 くり返しは展開しない。基準の実装を先に作る

- 漸化式の規則 $z_{n+1} = R(z_n, x, y, \text{パラメータ})$ を、**項を展開せず**に取り出す。$z_n$ を 2 つの実数の変数 $u + iv$ に置き換えた式を、変数 $(u, v, x, y)$ の `Program` にする
  （`Program` の変数は実数なので、複素数の変数はこの形で入れる）
- 先に Rust で画素ごとの基準の実装（`core/src/fractal.rs`）を作ってテストし、GLSL はそれを移す。GLSL の結果は `npm run test:gpu` で画素ごとに突き合わせる（12 章の G3・G5 と同じ決まり）
- 基準の実装は、テスト・カーソルの下の点の値・次元を測る（I4）・GLSL に移せない関数を使う式の予備の道（解像度を下げた画像）に使う

### 2.5 2D の画素ごとの材質の決まった名前

計算エンジンが作る GLSL は、決まった名前の関数だけを持つ。材質（`fractalMaterial.ts`）は種類ごとのループを持ち、この関数を呼ぶ:

| 種類 | エンジンが作る関数 | 材質のループ |
|---|---|---|
| 脱出時間 | `vec2 fStart(vec2 q)`（初項 $z_0$。`q` は画素の平面の座標）・`vec2 fStep(vec2 z, vec2 q)`（規則） | `z = fStart(q); for n < uMaxIter: if dot(z,z) > R² break; z = fStep(z, q)` → $\nu$ |
| ニュートン法 | `vec2 fStep(vec2 z, vec2 q)`（$z - f/f'$）・根の一覧は uniform | `z = q; for k: z = fStep(z, q); 一番近い根との距離 < ε なら break` → 根の番号と $k$ |
| 敷き詰め | 無し（材質が持つ） | Y1 の折り返し |
| 深い拡大 | `vec2 fDelta(vec2 Z, vec2 d, vec2 e)`（K2 の差の式） | K3 |

## 3. 決めたこと（2026-11-25。全部おすすめの案で決まった）

| # | 内容 | 決まったこと |
|---|---|---|
| D1 | 脱出時間の書き方 | 今の漸化式の行（`z_{n+1}=z_n^2+x+iy`・`z_0=0`）と、新しい行 `\operatorname{escape}\left(z_0,100\right)`（$z_0$ から 100 回まで）。`\operatorname{orbit}\left(z_0,N\right)` と同じ形で、$N$ はスライダーにできる。関数で書く形（`\operatorname{escape}\left(f,N\right)`）は作らない |
| D2 | ジュリア集合・ニュートン法の始点（初項に座標） | 定義の行 `z_0=x+iy` を許す。`escape`・`orbit` から使われるときだけ意味を持ち、行そのものは描かず「初項（座標を使う）」と出す |
| D3 | 脱出半径と色 | 脱出半径 $R$ は既定 256（⚙ で変えられる）。2.2 のなめらかな色は $R$ が大きいほどむらが少ない。回数の数え方は $R = 2$ と少しずれる（README に書く）。色は色相の環を $\nu$ で回す（周期は ⚙。既定 32 回で 1 周）、脱出しない点は黒 |
| D4 | L システムの書き方 | `\operatorname{lsystem}\left(\text{F},\ \text{F=F+F--F+F},\ 60^{\circ},\ n\right)`（初めの文字列・規則・角度・回数）。規則が複数なら 1 つの `\text{}` の中に `,` で並べる。角度はラジアン（今の式と同じ）で、新しく `60^{\circ}` を $60 \cdot \pi/180$ と読む（ほかの式 `\sin 30^{\circ}` でも使える） |

### F3: ニュートン法の図

- **担当**: B
- **平たい説明**: 方程式 $f(z) = 0$ の解をニュートン法 $z_{k+1} = z_k - \dfrac{f(z_k)}{f'(z_k)}$ で探すと、始点によってどの解にたどり着くかが変わる。
  始点ごとに、たどり着いた解で色を分け、何回で着いたかで明るさを変える。色の境目がフラクタルになる
- **触るファイル**: `core/src/fractal.rs`、`equation.rs`（`@newton`）、`latex.ts`、`fractalMaterial.ts`、`core/tests/fractal.rs`
- **やること**
  1. `\operatorname{newton}\left(f,N\right)`: $f$ は 1 変数の関数の名前（定義の行 `f(z)=z^3-1`）。$f'$ は `diff.rs` で作る（微分できない関数を含めば、その旨の誤り）
  2. 根を先に求める: 表示範囲の $64 \times 64$ の始点から CPU でニュートン法を 100 回まで回し、$\lvert f\rvert < 10^{-10}$ で止まった点を、距離 $10^{-6}$ でまとめる（16 個まで。超えたら近い順に 16 個）
  3. 材質: $z_0 = q$ から `fStep` をくり返し、どれかの根との距離が $\varepsilon = 10^{-4}$ 未満になったら止める。根の番号で色相（根を偏角の順に並べて色相を等分）、
     回数 $k$ で明るさ（$k$ が大きいほど暗い）。$N$ 回で着かなければ内側の色
  4. 根の位置に小さな点を描く（`Plot::Points` を一緒に返す）
- **完了の条件**: $f(z) = z^3 - 1$ で根が 3 つ（$1$・$e^{\pm 2\pi i/3}$。誤差 $10^{-10}$）。実軸の上の正の始点は全部 $1$ に着く。図が $120^\circ$ 回転で同じ（基準の実装で、
  画素を $120^\circ$ 回した画素と根の番号が対応する割合が 99% 以上）。`npm run test:gpu` で根の番号が基準の実装と 99% 以上同じ
- **README**: 「フラクタル」の段落にニュートン法

### I4: 次元を測る（ボックス計数・相似次元）

- **担当**: B（理由: 当てはめに使う箱の大きさの範囲の選び方で、数が大きくずれる）
- **平たい説明**: 図形を一辺 $\varepsilon$ の箱で覆うのに要る箱の数 $N(\varepsilon)$ が $\varepsilon^{-D}$ のように増えるとき、$D$ が次元。線なら箱を半分にすると数が 2 倍（$D = 1$）、

### K2: 摂動法の基準の実装（CPU）と深さの物差し

- **担当**: A（理由: 摂動法は、差の式・基準の軌道の取り替え（リベース）・桁のあふれのどれを間違えても、もっともらしい絵が出て気づきにくい）
- **平たい説明**: 画面の中心の 1 点だけを高い精度で計算し（基準の軌道 $Z_n$）、ほかの画素は「中心の軌道からのずれ $\delta_n$」だけをふつうの精度で計算する。
  ずれは小さいので、ふつうの精度でも桁が足りる
- **触るファイル**: `core/src/perturb.rs`（新規）、`core/src/fractal.rs`（多項式の判定）、`core/tests/deep_zoom.rs`
- **やること**
  1. 多項式の判定（D7）: 規則 $R(z, c)$ を $z$ と $c$（$= x + iy$。ジュリア集合なら $c$ は使わず、ずれは初項に入る）の多項式 $\sum a_{jk} z^j c^k$（係数は複素数の定数。スライダーの値で決まる）に展開する。
     次数は合わせて 16 まで。多項式でなければ「深い拡大は、多項式の漸化式（z_{n+1} = z_n^2 + c など）だけで使えます」で、深い拡大に入らない
  2. 差の式: $\delta_{n+1} = R(Z_n + \delta_n, C + e) - R(Z_n, C) = \sum_{(p, q) \ne (0, 0)} b_{pq}(Z_n)\, \delta_n^{\,p}\, e^{q}$、
     $b_{pq}(Z) = \sum_{j \ge p,\ k \ge q} a_{jk} \binom{j}{p} \binom{k}{q} Z^{j-p} C^{k-q}$。$\delta$ も $e$ も含まない項は**式の上で**消す（引き算で消すと桁が落ちる）。
     マンデルブロ集合なら $\delta_{n+1} = 2 Z_n \delta_n + \delta_n^2 + e$
  3. 基準の軌道: 中心 $C$（K1 の高い精度）で $Z_n$ を計算し、f64 に丸めて並べる。脱出したらそこまで
  4. 画素ごと: $e$ = 画素と中心の差（f64 で足りる。幅の何倍か × 幅）。$\delta_0 = 0$（ジュリア集合は $\delta_0 = e$、$e$ を式から外す）。
     毎回 $z = Z_m + \delta$ を作り、$\lvert z\rvert > R$ なら脱出。**リベース**（Zhuoran 2021）: $\lvert z\rvert < \lvert\delta\rvert$ になったか、$m$ が基準の軌道の終わりに来たら、$\delta \leftarrow z$、$m \leftarrow 0$
  5. 指数を分けた数: 幅が $10^{-290}$ より細かいと $\delta$ が f64 で 0 になるので、$\delta$ と $e$ を「f64 の仮数 + `i64` の指数」で持つ形も作る（ここでは CPU で、K3 の GPU の形を先に確かめる）
  6. 物差し `deep_report`: 下の場所と幅で、$32 \times 32$ 画素の整数の回数 $n$ を、(a) 摂動法と、(b) 全部の画素を高い精度で直接計算したもの（正解）で比べる
- **実装の土台**


- **完了の条件**（`core/tests/deep_zoom.rs`）
  - 場所: **ミシュレヴィッチ点** $c = i$（$z$ は $0, i, -1+i, -i, -1+i, \ldots$ と周期に入る）と $c = -2$（集合の左端）を中心にする。この 2 点の周りは、どの深さに拡大しても形が続く。
    適当な点（有名な座標を 30 桁ほどで切ったもの）を深く拡大すると、全部の画素が同じ回数の一色になって比べる意味が無いので使わない。
    画素の格子は半画素ずらす（$c = -2$ で実軸の上の画素を作らない。実軸の上の軌道は脱出せず、正解の計算に桁が要りすぎる）
  - 比べ方: $32 \times 32$ 画素の整数の回数 $n$ を、(a) 摂動法と (b) 全部の画素を高い精度で直接計算したもの（正解）で比べる。(b) の精度は、ビット数を 2 倍にしても
    全部の画素の $n$ が変わらないことを確かめた値を使う。どの場合も、32 × 32 画素の中に違う $n$ が 20 通り以上あること（一色でないこと）を先に確かめる

  | $10^{-30}$ | 10,000 | 99% 以上 |
  | $10^{-100}$ | 10,000 | 99% 以上 |

  (a) の時間はどれも 1 秒以内（ネイティブ。基準の軌道を含む）。違う画素は、(b) で回数が $N$ に近いもの（脱出するかどうかの境目）だけであることを、表で PR に貼る。
  リベースを切ると割合が下がる（リベースが効いている証拠）ことも表に入れる。

### Y2: アポロニウスのガスケット

- **担当**: C（理由: デカルトの円の定理の式で決まる）
- **平たい説明**: 互いに接する 3 つの円の隙間に、3 つ全部に接する円を入れる。できた新しい隙間にまた円を入れる、をくり返す
- **触るファイル**: `core/src/hyperbolic.rs`（または `fractal.rs`）、`equation.rs`（`@apollonius`）、`core/tests/hyperbolic.rs`
- **やること**
  1. `\operatorname{apollonius}\left(n\right)`（外の円の曲率 $-1$、内の円 $2, 2, 3$ の、曲率が全部整数になる例）と、`\operatorname{apollonius}\left(k_1,k_2,k_3,n\right)`（外の円の曲率 $k_1 < 0$ と、内の 2 つ）
  2. デカルトの円の定理: 曲率 $k_4 = k_1 + k_2 + k_3 \pm 2\sqrt{k_1 k_2 + k_2 k_3 + k_3 k_1}$、中心（複素数）$z_4 = \dfrac{z_1 k_1 + z_2 k_2 + z_3 k_3 \pm 2\sqrt{k_1 k_2 z_1 z_2 + k_2 k_3 z_2 z_3 + k_3 k_1 z_3 z_1}}{k_4}$。
     ± のうち、すでにある円でない方。新しい円ごとに 3 つの新しい隙間（深さ $n$ まで。半径が表示範囲の幅の $10^{-4}$ より小さい円は止める）
  3. 出力は円の線（`Plot::Points`。円ごとに半径に応じた点の数、最低 16）。円が 10 万個を超えたら「円が多すぎます（n を小さく）」
- **完了の条件**: $(-1, 2, 2, 3)$ で、深さ 1 で増える円の曲率が $\{3, 6, 6, 15\}$、深さ 6 まで全部の曲率が整数（$10^{-9}$）、円の数が深さ $n$ で $2 + 2 \cdot 3^n$。
  隣どうしの円が接している（中心の距離と半径の和・差の差 $10^{-9}$）。I4 の次元が $1.3057 \pm 0.05$
- **README**: 「フラクタル」の段落にアポロニウスのガスケット（双曲幾何とのつながり: メビウス変換で写しても同じ形の仲間になる）

## 6. 危ない所

- **F2 の 32 ビットの精度**: GPU は f32 なので、幅 $10^{-5}$ ほどからマンデルブロ集合の画素の座標が粗くなる（f64 の基準の実装と違う絵）。K1 の深い拡大に入る幅（$10^{-12}$）との間は、
  画素の座標を「f32 の基準点 + f32 のずれ」の 2 つに分けて渡して延ばす（df64 と同じ考え）。それでも足りなければ、深い拡大に入る幅を $10^{-5}$ に上げる（K2 の摂動法は浅くても正しい）
- **F0 の展開の道との混同**: `escape` の規則を、今の数列の展開（`term_value`）で $z_N$ にしてしまうと、1.2 のとおり遅く、深いとスタックがあふれる。規則の式だけを取り出す
- **K2 のもっともらしい間違い**: 摂動法の誤り（リベース漏れ・差の式の桁落ち）は「少し違うがきれいな絵」になる。必ず直接計算の正解（K2 の物差し）と比べ、割合を PR に貼る
- **K3 の GPU が止まる**: 回数の多い画素が 1 コマに入りきらないと、ブラウザが WebGL の文脈を失う。1 コマの回数の上限（2,000 回）を守り、文脈を失ったら上限を半分にして描き直す
- **I0・I1 の数の爆発**: L システムは段ごとに長さが何倍にもなり、IFS の深さは $m^n$ 個になる。作る前に数を数えて打ち切る（固まらない）
- **Y1 の縁の近く**: $\lvert z\rvert \to 1$ で、鏡映の回数が増え、32 ビットで $1 - \lvert z\rvert$ の桁が落ちる。上限の回数で止まった画素は縁の色（灰色）にし、欠けを黒い穴にしない
- **I4 の次元の数字の信じすぎ**: ボックス計数は、当てはめる箱の大きさの範囲で数が変わる。「≈」と段の数を必ず出し、README に「目安」と書く
