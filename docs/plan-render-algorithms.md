# 計画: 描画の種類ごとの精密化・最適化と、導入するアルゴリズム

この文書は、次の 3 つを 1 か所にまとめたもの。

1. **描画の種類の一覧**（1 章。T01〜T25）: このアプリが「何を、どの道で描いているか」。種類ごとに、今の方法・場所・弱点を書く
2. **種類ごとの系譜と、導入するアルゴリズム**（2 章）: その種類がどんな歴史で今の形になったか、次に何を入れるか
3. **アルゴリズムの一覧**（3 章。A01〜A74）: 大学以降の数学・競技プログラミング・最近の研究から選んだもの。出典・使い所・難しさつき

その上で、**実行の順序**（4 章。P0〜P5）と、守ること・測り方（5 章）、未確認の所（6 章）を書いた。
計画を実行する人（利用者・実装を担当するエージェント）が、1 ステップずつ取って進められるようにしてある。

## 0. 読み方

- 記号: **T** = 描画の種類、**A** = アルゴリズム、**P** = 実行のステップ。`docs/plan-hard-tasks.md` の S・G、`docs/plan-math-notation.md` の M とは別の番号
- **確認の印**（3 章の最後の列）:
  - **✔** … 2026-11-18 に、ネットで原典または解説を確認した（6 章に出典）
  - **△** … 知識から書いた。実装の前に原典を読むこと（年・著者の細部は違っているかもしれない）
- 「今の方法」は README とコードを読んで書いた（2026-11-18 時点。コミット `a985b00` まで）。コードで確かめていない所は「README による」と書いた
- 効果の大きさは**見込み**で、測った値ではない。各ステップの「完了の条件」の数字は、測って決め直す前提の目安
- 利用者のテスト表（`プロット殺し関数テスト表 - 3D・多次元.csv`）の行は、`S-04` のように ID で書く。判定の列が空なので、今の合否は書いていない

### 0.1 方針: 酷いものだけ直し、今ので良いものはそのままにする

すべての種類に手を入れる計画ではない。種類ごとに、次の 3 つに分ける。**C（現状維持）は、測って悪化が出ない限り手を付けない**。
B は「その種類で困った例が出たら」やる。A だけを先にやる。

| 判定 | 意味 |
|---|---|
| **A 直す** | 誤り・崩れ・機能の欠けが実際に出ている |
| **B 困ったらやる** | 困った例はまだ少ない。テスト表の判定・利用者の報告で必要になったら |
| **C 現状維持** | 今ので十分。手を付けない（悪化したときだけ戻す） |

### 0.2 現状は C・B でも、別のアルゴリズムで格段に良くなりそうなもの（大化け候補）

「今ので良い」ものでも、**アルゴリズムを替えると桁が変わる**可能性があるものは、**試作して測り、採否の基準を超えたときだけ採用する**（4 章の P6）。
基準に届かなければ、そのままにする。**効果が文献で確かめられているものは少ない**ので、根拠の種類を書いた。

| ID | 種類 | 候補（3 章の ID） | 格段になる理由 | 見込み（根拠の種類） | 先にやる小さい実験 → 採否の基準 |
|---|---|---|---|---|---|
| Q1 | T24・T13 | 重い特殊関数・ζ の高速な代理（A36 AAA、A35 chebfun 型。ζ は格子の行ごとに A42） | `hypU`・`hankelH1` などは 1 評価 10〜20 µs、ζ の色分けは重いまま。有理関数の評価は数十回の演算で済む | 1 評価で 100 倍級（算術による推測）。**誤差の保証が無い**ので、描画の格子の値だけに使い、区間演算・見落とし検出には使わない | `hypU`・ζ で代理を作り、時間と誤差を測る → **50 倍以上で誤差 1e-9 以内の範囲が使える**なら採用 |
| Q2 | T04・T01 | 区間のふくらみ対策（A15 アフィン演算） | ジャイロイドのように同じ変数が何度も出る式は、区間が広がって光線の二分が深くなる（最重 39 ms） | 不明（推測）。広がりが原因かを先に確かめる | Rust の基準実装（`pixel.rs`）で、ジャイロイドの光線 1 本あたりの二分の回数を、区間演算とアフィン演算で数える → **回数が半分以下**なら GLSL に移す |
| Q3 | T05・T06・T10 | 不等式の領域の GPU の式を、タイルごとに短く（A19 の枝の刈り込み） | 領域は `G = max G_i` なので、`max` の効かない枝を捨てられる。Keeter の例では 6056 命令が平均 28 命令。**ジャイロイドのような `sin`・`cos` の和には `min`・`max` が無く効かない** | 文献の数字（Keeter 2020 ✔）。ただし式の形による | 不等式 8 本の領域の式で、タイルごとの平均の命令数を Rust で数える → **平均が 1/3 以下**なら実装 |
| Q4 | T22 | カーソルの下の点の BVH（A12。自前で 200 行ほど、または `three-mesh-bvh`＝新しい依存） | three.js の標準は三角形の総当たり（O(n)）。BVH は O(log n) | 計算量の差は ✔。**数字は未確認**（90k 三角形で効いたという報告が 1 件） | 三角形 100 万個の応答時間を測る（P0-4）→ **今が 16 ms を超える**なら実装 |
| Q5 | T23 | 式の JIT（実行時に WASM を生成。A75） | 命令ごとに 256 点の配列を読み書きするのをやめ、1 つの関数に融合する | Fidget の JIT は解釈型の約 2.4 倍（2048³、M1 Max。✔）。ただし Fidget の JIT は x86_64・aarch64 向けで、wasm32 では使えない（自前の設計になる） | ジャイロイドの命令列を手で WASM に直して 256 点の時間を比べる → **2 倍以上**なら実装 |
| Q6 | T23・T24 | WASM SIMD（A74） | 加減乗除・`min`・`max` を 2 点ずつ（`f64x2`）。**最大 2 倍**で、桁は変わらない | 上限は算術。対応状況は ✔（Chrome 91・Firefox 89・Safari 16.4 から）。見送った理由の「互換性」は、今は弱い | `chunk_real` の四則だけ SIMD にして測る → **1.3 倍以上**なら採用。ただし SIMD なしの WASM も出す必要があり、大きさが 2 倍近くになる点が本当の費用 |
| Q7 | T10 | 霧に、距離で歩幅を変える歩き方（A49 + A46） | 霧は境目の面より十数倍重い。境目から遠い所を大きい歩幅で飛ばせば、標準にできる | 不明（推測） | 実機で、今の霧と歩幅可変の霧のコマの時間を比べる → **3 倍以上**で、境目の見た目が変わらなければ霧を標準の選択肢に |
| Q8 | T18 | 2D の LIC・FTLE（A56・A58） | 矢印と少数の流線では見えない流れの全体像（渦・分離面）が見える。**見た目の質が変わる**（速さではない） | 質的（LIC は 1993 年からの定番 ✔） | 平面の `(-y, x)`・ローレンツの断面で、LIC の 1 枚の絵を作る → **利用者が「矢印より分かる」と判断**したら採用 |
| Q9 | T20 | `max_t`・`min_t` を分枝限定で保証つきに（A69 + A18） | 今は範囲を 64 等分した点の近似。細い山は見落として、知らせない | 正しさの質的な差（算術で確かめられる） | `max_{t∈[0,1]} exp(-10⁴(t − 0.3123)²)`（正解 1）。等分では 0 に近く、分枝限定では 1 になるか → **保証つきで 10 倍以内の時間**なら採用 |
| Q10 | T21 | 動いている間の時間方向の再利用（A50） | 回している間も、止まったときの細かさを保てる | 不明（推測が大きい）。実装は大きい | まず止まったときとの見た目の差が実害かを、利用者に聞く → 実害があれば試作 |

**やらないと決めてよいもの**: 上の表に入れなかった C の種類。Q1〜Q10 のどれかを試すのは、その種類の判定を C から B に上げるのと同じ。

## 2. 種類ごとの系譜と、導入するアルゴリズム

各項は「**系譜**（どんな歴史でこの形になったか）→ **限界**（今のやり方で難しい所）→ **導入**（3 章の ID）→ **物差し**（効いたかの測り方）」。
**系譜を書くのは、次の一手が歴史の延長にあると、選びやすく、失敗の理由も分かりやすいから**。

### T01 陽関数の曲面

- **系譜**: 一様格子で標本 → 区間演算で「必ず無い・必ずある・分からない」に分ける（Tupper 2001）→ 最も新しい頂点の二分（Mitchell 1991・Maubach 1995。△）→ 多項式の近似（chebfun2。Townsend・Trefethen 2013。△）
- **限界**: 特殊関数・複素数の式は区間演算の上で見落としうる。細い極は壁を切り分けで描くが、極の種類は分からない
- **導入**: A21（ball 演算で特殊関数にも区間を）、A38（二階微分で曲率に合わせた細分）、A35（chebfun2 型の近似で、同じ式を何度も評価するのを避ける）、A18（制約伝播で箱を縮める）
- **物差し**: `core/tests/shape.rs` の `shape_report`（欠け・余計・破片）、`bench`。テスト表 Z-01〜Z-08

### T02 陰関数の曲面（メッシュ）

- **系譜**: Marching Cubes（Lorensen・Cline 1987）→ 曖昧な場合の判定（Nielson・Hamann 1991、Chernyaev 1995）→ Surface Nets（Gibson 1998）→ Dual Contouring（Ju ほか 2002。ヘルミートデータ = 交点と法線で鋭い辺を再現）→ Dual Marching Cubes（Schaefer・Warren 2004）→ Manifold Dual Contouring（Schaefer・Ju・Warren 2007。簡略化しても多様体）→ 区間演算で位相を保証（Plantinga・Vegter 2004）→ GPU で直接（Keeter 2020）
- **限界**: Surface Nets は頂点を面の中心に置くので、鋭い辺・角が丸まる（S-11）。格子より細い成分は「疑わしい所を細かく」で拾うが、拾えた保証が無い。特異点では法線が不定（S-04・S-05）
- **導入**: A01（Dual Contouring）、A02（Dual Marching Cubes）、A03（曖昧さの解消）、A04（位相を保証する細分）、A13（連結成分で破片・成分を数える）、A06（特異点の検出）、A11（ロバストな述語）、A51（疎な階層構造）、A52（GPU でメッシュ化）
- **物差し**: `shape_report`（欠け・余計・破片）。テスト表 S-01〜S-15、`docs/audit/*.tsv`

### T03 媒介変数の曲線・曲面・立体

- **系譜**: 一様なパラメータ刻み → 弦と曲線の距離が許容以下になるまで再帰的に分ける → 曲率・弧長で刻みを決める → 曲線の間引き（Ramer・Douglas・Peucker。Visvalingam・Whyatt）
- **限界**: 極で面積が 0 の三角形ができ法線が NaN（PS-01）。K-01 のように 10⁴ 周する曲線は頂点が多すぎる。自己交差が見えない（PS-03・PS-05）
- **導入**: A08（曲率適応の間引き）、A38（二階微分で解析的な法線と曲率）、A07（Bézier clipping で自己交差）、A67（掃引線で線分の交差）
- **物差し**: `bench`、テスト表 PS-01〜PS-05・K-01〜K-04

### T04 画素ごと（GPU）の 3D 陰関数

- **系譜**: 球トレーシング（Hart 1996。距離の下限だけ進む）→ 区間演算の光線（Mitchell 1990）→ アフィン演算（Comba・Stolfi 1993。Knoll ほか 2009）→ セグメントトレーシング（Galin ほか 2020。区間ごとの局所リプシッツ定数）→ Massively Parallel Rendering（Keeter 2020。タイルと、式の枝の刈り込み）→ Lipschitz Pruning（Barbier ほか 2025）
- **限界**: 区間が広がりすぎる式（同じ変数が何度も出る）で光線の二分が深くなる。特殊関数・複素数は GLSL に移していない
- **導入**: A19（タイル + テープ刈り込み）、A20（Lipschitz の枝刈り・擬似区間）、A15（アフィン演算）、A50（時間方向の再利用）
- **物差し**: `?bench=1`（コマの時間）、`npm run test:gpu`（G3〜G5。Rust の基準と画素ごとに比べる）

### T05 画素ごと（GPU）の 2D 曲線・領域

- **系譜**: 画素の箱ごとの区間演算（Tupper 2001。GrafEq）→ 距離の見積もり `F/‖∇F‖` で太さをそろえる（Quilez）→ タイル階層（Keeter 2020 の 2D）
- **限界**: T04 と同じ
- **導入**: A19、A05（線の連続法で高品質な線）、A06（特異点を点で示す）
- **物差し**: `npm run test:gpu` の G4

### T06 連立方程式・不等式

- **系譜**: 数値で符号の変化を探す → ニュートン法で寄せる → 代数的に解く（Buchberger 1965 のグレブナー基底）→ 高速化（F4・F5。Faugère 1999・2002）→ 数値代数幾何（ホモトピー続行。HomotopyContinuation.jl）→ 実代数幾何（CAD。Collins 1975）
- **限界**: グレブナー基底は有理数が `i128` に収まる間だけ。辞書式順序で直接求めるので、式が大きいと基底が大きい。次元が 1 の解（曲線）は無限個として退ける
- **導入**: A22（グレブナー基底の改良）、A23（終結式）、A24（実根の厳密な個数）、A17（区間ニュートンで解の存在を証明）、A25（ホモトピー続行 + 証明）、A26（CAD）、A06（特異点）、A07（曲線の交点）
- **物差し**: `core/tests/systems.rs`（`curve_report`）、`tangent_points_from_groebner_basis`

### T07 曲線・点・線の見た目

- **系譜**: 太さ 1 の線（WebGL の制限）→ 幅のある線（三角形のリボン。LineSegments2）→ 管（フレネ枠 → 回転最小フレーム。Wang ほか 2008）
- **限界**: 管は無い。管を作るならフレネ枠は変曲点で反転する（K-03）
- **導入**: A09（回転最小フレームの管）、A08（曲率適応の間引き）
- **物差し**: テスト表 K-03・K-04

### T08 切り口・ふた

- **系譜**: ステンシルバッファでふた（△）→ 多面体の断面を幾何的に作る
- **限界**: 複雑な立体で、ふたが半透明と重なると濃さが変わる
- **導入**: A48（順序に依存しない透明）、A14（輪郭木で、切る値ごとの成分の数）
- **物差し**: `core/tests/systems.rs` のふたの面積の検査

### T09 伝達関数のボリューム

- **系譜**: 重ね塗りの式（Levoy 1988・Drebin ほか 1988）→ シアーワープ（Lacroute・Levoy 1994）→ 事前積分（Engel・Kraus・Ertl 2001）→ 空の所の飛ばし（min-max 八分木・距離マップ・階層 DDA）→ 疎な階層格子（VDB・NanoVDB）
- **限界**: 歩数が固定で、空の所も歩く。勾配が格子の差分で粗い。視点が箱の中だと描かれない
- **導入**: A45（事前積分）、A46（空の所の飛ばし）、A47（三次補間）、A49（距離場）
- **物差し**: `?bench=1&only=…` のコマの時間、`tools/gpu-g5`

### T10 不等式領域の霧

- **系譜**: 領域を格子の 0/1 で塗る → 符号つき距離場（SDF）で境目を細く → 距離場の作り方（高速行進法。Sethian 1996）→ 線形時間のユークリッド距離変換 → GPU の距離変換（Jump Flooding。Rong・Tan 2006）
- **限界**: 今は `G/‖∇G‖` の見積もりで、`G` がなめらかでないと境目が点々になる
- **導入**: A49（真の距離）、A46（空の所の飛ばし）、A27（多面体なら厳密な頂点）
- **物差し**: ソフトウェア描画の fps（README の 0.9 fps）、実機のコマの時間

### T11 範囲で重ねた立体・等値面を何枚も・断面の塗り分け

- **系譜**: スカラー場の等値面 → 等値面の位相（臨界点・Morse 理論）→ 輪郭木・Reeb グラフ（Carr・Snoeyink・Axen 2000）
- **限界**: 位相が変わる値（M-02: `sin x + sin y + sin z = c` の c = ±1, ±3）で破片・穴が出る
- **導入**: A14（輪郭木で成分の数）、A29（臨界値を `∇F = 0` を解いて求める）、A04（位相を保証する細分）
- **物差し**: テスト表 M-02

### T12 値の色付け

- **系譜**: 虹色（知覚的に不均一）→ viridis（2015）・turbo（2019）→ CIELAB・CAM16-UCS → OKLab（Ottosson 2020）→ 色覚の多様性のシミュレーション
- **限界**: 範囲は「9 割点」の 1 通り。色覚の違いを検査していない
- **導入**: A53（色空間と色覚シミュレーション）、A55（頑健な正規化・symlog）
- **物差し**: 色の目視と、色覚シミュレーション後の区別（実装後に決める）

### T13 複素数の色分け

- **系譜**: 領域の色分け（Farris 1998）→ 位相肖像（Wegert 2012）→ 零点・極の個数を偏角の原理で数える（Delves・Lyness 1967）→ 解析接続で多価関数を連続に描く
- **限界**: 零点・極の位置が色から読みにくい。リーマン面のサンプルでは分岐切断で色が飛ぶ
- **導入**: A54（対数の等高線・零点と極の個数）、A65（解析接続）
- **物差し**: 色分けのサンプル（`複素` で掃引）

### T14 面・線の見た目

- **系譜**: 前後で並べ替える半透明 → 深度剥ぎ（Everitt 2001）→ 重みつき平均（McGuire・Bavoil 2013）→ モーメントを使う（Münstermann ほか 2018）
- **限界**: 複数の半透明の面（等値面を何枚も）で前後が崩れる
- **導入**: A48（WBOIT・MBOIT）
- **物差し**: 等値面 64 枚の見た目と時間

### T15 座標軸・目盛り・ラベル

- **系譜**: 固定間隔 → きりの良い値（1・2・2.5・5 × 10ⁿ。実装済み）→ 文字の描画（符号つき距離場のフォント。Green 2007。△）
- **限界**: ラベルのテクスチャ作成が重い
- **導入**: A66（キャッシュのキー設計）、符号つき距離場のフォント（△。新規の npm パッケージは不要）
- **物差し**: `?bench=1` の起動時間

### T16 n 次元の回転・射影・断面

- **系譜**: 平面ごとの回転（Givens 1958）→ 四元数（Hamilton 1843）→ SO(4) = 左右の単位四元数の組（Cayley 1855）→ 幾何代数のローター（Clifford・Hestenes）→ 回転群の上の補間（指数写像・対数）→ 立体射影（共形）
- **限界**: 角度の補間が成分ごと（回転群の上の最短経路でない）。輪郭だけ描く機能が無い。無限遠（M-04）
- **導入**: A62（Cayley 分解・指数写像・再直交化）、A63（立体射影）、A64（見かけの境界）、A65（解析接続）
- **物差し**: テスト表 M-04、`?bench=1&only=次元`（再生中の往復時間）

### T17 座標系と移行

- **系譜**: 曲線座標（Lamé）→ 計量テンソルと法線の変換 → 微分同相写像の補間
- **限界**: 座標系の特異点（極・原点）で法線が不定
- **導入**: A38（ヤコビ行列を二重数で）、A08（座標系で伸びた所だけ細かく）
- **物差し**: 座標系のサンプル（`座標` で掃引）

### T18 ベクトル場・流線・常微分方程式

- **系譜**: 矢印（hedgehog）→ 流線 → 線積分畳み込み（LIC。Cabral・Leedom 1993）→ 高速 LIC（Stalling・Hege 1995）→ 等間隔の流線（Jobard・Lefer 1997）→ 臨界点とトポロジー（Helman・Hesselink 1989）→ 有限時間リアプノフ指数と Lagrangian coherent structures（Haller 2001・Shadden ほか 2005）→ 幾何学的数値積分
- **限界**: 矢印 9³ と少数の流線では、渦・分離面が分からない。硬い方程式は未対応
- **導入**: A56（LIC）、A57（等間隔の流線）、A58（FTLE）、A59（臨界点の分類）、A60（積分の方法）、A61（流面）
- **物差し**: 既知の場（`(-y, x, 0)`・ローレンツ）の再現。ODE のテスト（`core/src/ode.rs`）

### T19 積分・総和の可視化

- **系譜**: リーマン和の長方形（教科書の図）→ 数値積分の可視化（Simpson・Gauss の点）→ 適応型の区間の分割をそのまま見せる
- **限界**: 「積分の値の意味」は見せるが、「計算の中身」は見せない
- **導入**: A30・A31・A32・A33・A34（計算そのもの）、**可視化の追加**: 適応型の積分が分けた区間・誤差の大きい所を表示（`quad.rs` の区間の一覧を返す。新しいアルゴリズムではなく、既存の結果の見せ方の拡張）
- **物差し**: `core/tests/textbook_regions.rs`（40 の領域）、`single_integrals`

### T20 行列・集合・論理の図形

- **系譜**: ガウスの消去法 → 固有値（QR 法。Francis 1961）→ 集合の厳密な演算（CAD）→ 大域最適化（分枝限定。Moore・Skelboe）
- **限界**: `∃`・`∀`・`max_t` は等分した点の近似（32〜64）。固有値は未対応
- **導入**: A69（分枝限定で `max_t` の厳密化）、A26（CAD で `∃`・`∀` の厳密化）、A18（制約伝播）、A27（1 次不等式の領域）
- **物差し**: `core/tests/notation.rs`

### T21 動いている間の品質

- **系譜**: 固定の LOD → 時間に応じた画素密度（動的解像度）→ 時間方向の再投影（TAA。△）→ 注視点を中心に細かく（foveated。△）
- **限界**: 間引きの粗い版は作り直し。前のコマの結果を使わない
- **導入**: A50（時間方向の再利用）、A10（簡略化メッシュ）
- **物差し**: `?bench=1` のコマの時間・95% 点

### T22 カーソルの下の点・視点操作

- **系譜**: 三角形の総当たり → BVH（SAH・LBVH。Karras 2012）→ 球トレーシングでの直接求解
- **限界**: 三角形が多いと遅い可能性
- **導入**: A12（BVH）、A68（空間ハッシュ）
- **物差し**: 100 万三角形での応答時間（未測定。まず測る）

### T23 式の評価

- **系譜**: 木の評価 → 命令列（バイトコード）→ JIT → 構成的な式の変形（等式飽和。egg 2021）→ 数値的に安定な書き換え（Herbie 2015）
- **限界**: 命令数の多い式の区間演算・200 項の総和・ガウス・ルジャンドルの和の式

- **物差し**: `wbench`（式ごとの時間。スクラッチパッドの測定ツール）、`bench`

### T25 積分・総和・微分

- **系譜**: Newton–Cotes → Gauss（1814）→ Romberg（1955）→ Clenshaw–Curtis（1960）→ Kronrod（1964）→ QUADPACK（1983）→ tanh-sinh（Takahasi・Mori 1974）→ 振動積分（Filon・Levin・Olver）→ 多次元（Genz・Malik 1980）→ 準モンテカルロ

## 5. 測り方と守ること

**測る道具**（すでにあるもの）:
- 形の物差し: `cargo test --release --test shape shape_report -- --ignored --nocapture`（欠け・余計・破片）
- 時間: `cargo test --release --test bench -- --ignored --nocapture`、`?bench=1&only=…`（実際の画面。コマの時間・往復）
- 積分: `cargo test --release --test textbook_regions -- --nocapture`（40 の領域。相対誤差 1e-6 を超えたら落ちる）
- 連立方程式: `cargo test --release --test systems curve_report -- --ignored --nocapture`
- 画面のサンプル全部: `?bench=1&set=samples`（誤り・固まった時間・往復・コマ。約 15 分）
- GPU: `cd web && npm run test:gpu`（Rust の基準と画素ごとに比べる）
- 結果の指紋: ネイティブ・WASM の出力を式ごとに文字列にして比べる（前後でビットまで同じか。スクラッチパッドの `whash`・`wfeat` と同じ考え方）

**守ること**:
1. **標準は変えない**。新しい道は、式の ⚙ の選択または URL の引数で並べて、同じ式で比べてから切り替える（GPU の道を入れたときと同じ）
2. 1 ステップ = 1 PR = 1 つの種類。`cargo test --release`・`npm test`・`npm run check`・`?bench=1&set=samples` の掃引が全部通ること
3. **WASM の大きさに予算を持つ**。今の gzip は約 814 KB（積分の変更の時点。その後グレブナー基底・`solve.rs` を足したので、最初に測り直すこと）。1 ステップで足してよいのは目安 +50 KB（グレブナー基底・積分・CAD は大きくなりやすい）。足したら 1 章の表に書く
4. **互換性**: SIMD は見送り中。スマートフォンは既定がメッシュなので、メッシュの道が悪化しないこと
5. **新しい依存（npm・Rust の crate）は許可が要る**。前回、npm パッケージの追加は許可されなかった。多倍長整数・BVH・色の変換などで要るときは、先に利用者に聞く。自前の実装で済むかを先に考える
6. 誤差を保証しないもの（AAA・準モンテカルロ・FTLE）は、画面か説明に「近似」と出す。README の「近似が混ざる」の欄に書く
7. 速くした結果が変わるなら、前後の差を表にして、改善か悪化かを書く（今回の `nCr` のように丸めの差だけなら書くだけでよい）

## 6. 未確認・注意

**今回の調査で確認できなかったもの**（検索で見つからなかった。△ のまま）: Kovesi の色地図の論文、Felzenszwalb・Huttenlocher の距離変換の論文、Gil・Segura・Temme の本の内容。

**確認して分かった注意**:
- **Lipschitz Pruning は 2025 年**（Eurographics 2025、Computer Graphics Forum 44 巻 2 号）。2024 年ではない
- **Keeter の「勾配は新しい区間」（2025）は、リプシッツ性が前提**。式が Lipschitz でないと成り立たず、Prospero（Lipschitz でない）では区間演算のほうがわずかに速かった（512² で 12 ms 対 18 ms）。**区間演算を置き換える前提で計画しない**
- **AAA は誤差の保証が無い**。近似した関数を使うときは、保証の要る所（区間演算・メッシュの見落とし検出）では使わない
- **Odlyzko–Schönhage は 1 点の評価を速くしない**（等間隔の多数の点で FFT）。ζ の格子の評価（複素数の色分けの格子）では効く可能性があるが、格子が等間隔でないと使えない
- **F4・F5 が Buchberger 法より速いとは限らない**。Isabelle/HOL の実装での比較では F4 のほうが遅い例があり、別の報告では対称性のない入力で大差ないとされている（どちらも実装に依存し、決着していない）。グレブナー基底の改良は、F4 に替えることより、係数の爆発（モジュラー計算）と辞書式への変換（FGLM）を先に見る
- **WASM SIMD は、Chrome 91・Firefox 89・Safari 16.4 から使える**。互換性を理由に見送ったのは、今は弱い理由。ただし `f64x2` は 2 レーンなので最大 2 倍で、SIMD なしの版も出す必要がある
- **BVH の効果は、計算量（O(n) → O(log n)）は確かだが、100 万三角形での数字は確認できなかった**。先に今の応答時間を測る
- **Fidget の JIT は x86_64・aarch64 向けで、wasm32 では使えない**。WASM を実行時に生成する案（A75）は自前の設計で、効果は未確認
- **ホモトピー続行の `certify` は、「証明できない」が「解が無い」の意味ではない**
- **tanh-sinh は、滑らかな関数ではガウス型に劣る**。端が特異なときだけ使う
- **HC4-Revise は、同じ変数が複数回出る式では最適でない**（Mohc で単調性を使う改良がある）
- **Chebyshev 近似は、全体の次数で分解を決める**ので、局所的に細かい関数には向かない（区間ごとに分ける必要がある）

**この文書が前提にしていること**: 「描画の種類」は 25 に分けたが、分け方は 1 つの案。T09・T10・T11 を 1 つにまとめる、T19・T20 を分けるなど、実行する人が変えてよい（ID を変えたら、2〜4 章の参照も直すこと）。
