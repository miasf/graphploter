## 2. 書き方（全部の文書で同じ）

- 形は `plan-locus-complex-integral.md` と同じ: 0 進み具合 / 1 調べた結果 / 2 全体の決めごと / 3 決めてもらうこと（おすすめ付き） /
  4 ステップの一覧 / 5 ステップごとの指示書（目的・触るファイル・やること・やらないこと・完了の条件・壊してはいけないもの・README） /
  6 危ない所 / 7 ほかの計画との関係
- **各ステップに「担当: A / B / C」と理由を 1 行**（段階は `docs/agent-tiers.md`）
- **各ステップに「実装の土台」**: 新しいファイルと関数の形（Rust・TypeScript の型の下書き）、データの形、処理の流れの擬似コード、
  今のコードのどこにつなぐか（ファイル名と関数名。行番号は目安）。2 章に「全体の作り」（新しいファイルの表・データの形・画面までの道）を置く。
  土台は出発点で命令ではない、と冒頭に書く（合わなければ直して 0 章に「計画との違い」）。手本は `plan-riemann-topology.md`
- **⚙ の項目を足す道**（手本は曲率の色分け N2）: `web/src/lib/types.ts` のビットの定数 → `plot.worker.ts` の `req.flags & (…)`（キャッシュの鍵。新しいビットはここに足す）→
  `core/src/lib.rs` の `plot` の中、`build` の直後 → `MeshResult` のフィールドと getter → `ExpressionItem.svelte`。
  `flags` のビットは 0〜7 が使用中で、文書 1 が 8（256）・9（512）、文書 2 が 10（1024）、文書 3 が 11（2048）を予約した（文書 4 はビットを使わない）。数を渡す設定は `plot` の引数を増やさず、
  `geodesic_spec` のような `#[wasm_bindgen]` の設定関数にする（テストが `plot` の 25 個の引数を位置で渡しているため）
- **3 章の「決めてもらうこと」には必ずおすすめを付ける**。利用者は「全部おすすめで」と答えることが多いので、そのときは 3 章を「決めたこと」に書き換える
- 日本語。数式は LaTeX。ステップの名前は、使っている文字（S・G・H・M・N・L・Z・Q・P・R・U・V・W・X・F・I・K・Y・B・C・E・J。T と A は `plan-render-algorithms.md` の種類とアルゴリズムの番号、D は各文書の「決めること」の番号）と重ならない文字にする。
  文書 5 は Q の番号と O0〜O5 を使った（1 文字の名前は全部使い終わった。新しい計画は 2 文字の名前にする）
- **書く前に、計算エンジンに式を入れて今の動きを確かめる**（`core/tests/` に一時的なテストを置いて `cargo test --release --test …`。
  終わったら消す。エラーの中身は WASM 以外では読めないので、`std::panic::catch_unwind` で成功・失敗だけ見る）
- 完了の条件は、数で確かめられる形にする（正解の値・誤差・時間）

## 3. 文書ごとの範囲（会話で決まったこと）

### 文書 1: リーマン面と位相幾何

- N8（`plan-math-notation.md` 7.3）を、ステップごとの指示書にする。試作（$\sqrt z$・$\log z$）で続けるか決める段を最初に置く
- 位相幾何は利用者が履修していないので、範囲はこちらで決め、各項目に平たい説明を付ける:
  - 測る: オイラー標数 $\chi$・種数・連結成分・縁の数・向き付け可能か
  - 作る: 正方形の辺の貼り合わせ（球・トーラス・クラインの壺・射影平面・メビウスの帯）
  - 変形: 2 つの曲面のあいだのなめらかな変形（コーヒーカップとドーナツ）
  - 結び目: 曲線を管で描く・絡み数・有名な結び目
  - やらない: ホモロジー群の一般の計算・基本群・結び目の不変量の多く
- $\chi$ の判定を N8 の前に入れ、リーマン・フルヴィッツの公式で N8 を確かめる物差しにする

### 文書 2: 解析

- **近似値の表示**（Desmos のように、式の横に値を出す）。今は定数の式の値を、描いたメッシュの高さ（f32。7 桁ほど）から読んでいる
  （`web/src/App.svelte` の「陽関数の高さ」の所）。f64 で計算した値を常に出す。複素数・定義した関数の値 $f(2)$・リストも
- **厳密値はやらない**（利用者が、将来 Wolfram のようなアルゴリズムを自分で作りたい）。近似値の表示は、後で厳密値を足せる作りにし、
  文書の 7 章に「厳密値は将来の別計画」と 1 行書く
- **方向微分**: 記法 $D_{\mathbf u} f$ と、向き $\mathbf u$ を回すと切り口の曲線・接線が動き、傾きを $\theta$ の関数として描く図
- **多変数の極限**: 利用者の答えは「(a)・(b) どちらも」:
  - (a) 極限の式の中に積分・級数が入る場合
  - (b) 広義積分・級数の収束・発散の判定も極限の仲間として扱う
  - 数値では「存在する」とは言えない。「存在しない」（違う値に近づく 2 つの経路）と、極座標 $g(r, \theta)$ の図を中心にする
  - 1 変数の `\lim` はある（`core/src/limit.rs`）。広義積分のテストは `core/tests/improper.rs`
  - 追加の要望（3 章を決めたとき）: → の左を式にする（$\lim_{2x\to1}$・$\lim_{x^2\to0}$。多変数も）、ベクトルの極限（中身がベクトル・`\lim_{\mathbf x\to\mathbf a}`）、
    近づく先・中身に座標を置く（$\lim_{t\to x}$。結果は座標の関数として描く）。文書の X5〜X7

### 文書 3: フラクタルと双曲幾何

- 式から: 利用者の $z \mapsto f(z)$ の脱出時間の図・ニュートン法の図・IFS・ボックス計数の次元。画素ごとの GPU（12 章の G 系）に乗せる
- **作りやすくする機能**: よく見るフラクタルを用意する（コッホ雪片・シェルピンスキーの三角形とカーペット・カントール集合・ドラゴン曲線・
  ヒルベルト曲線・バーンズリーのシダ・マンデルブロ・ジュリア・メンガーのスポンジ・マンデルバルブ）、L システム、アフィン写像の並びの IFS、
  再帰の深さのスライダー
- **深い拡大をやる**（利用者の希望）: 摂動法（基準の 1 点の軌道だけ高い精度、残りは差を GPU で）と、N9（表示範囲の中心からの相対座標）
- 双曲幾何: ポアンカレ円板・メビウス変換・敷き詰め。アポロニウスのガスケットはフラクタルと重なる
- 今ある: `orbit`・`orbitpoints`・`bifurcation`・`cobweb`（README の数列の段落）
