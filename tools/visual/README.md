# 見た目の比較（描画の回帰チェック）

描画の計算（`core/`）を変えたときに、**どの式の見た目が変わったか**を、コミットどうしで並べて確かめる道具。
`shape_report` の数字（欠け・余計）は、画面で見える崩れ（細い隙間・裏返り・破片・形の変わり方）を拾えないことがあるので、
描画を変えるステップでは、これで前後を見比べてから先に進む。

## 使い方

```sh
# 1. コミットごとにエンジンをビルドして、cases.tsv の式のメッシュを書き出す（1 コミット 1 分ほど）
tools/visual/dump_revs.sh /tmp/vis 30b2332 HEAD WORK    # WORK は今の作業ツリー（コミットしていない変更を含む）

# 2. 全部のコミットのメッシュを同じ視点・同じ光で描いて並べる
node tools/visual/render.cjs /tmp/vis 30b2332 <HEAD の短いハッシュ> WORK
# → /tmp/vis/report/index.html（変化の大きい順の一覧）、式ごとの画像、changes.tsv
```

- `VISUAL_ONLY=stairs` … 名前にその文字を含む式だけ（`dump_revs.sh` の書き出しにも、`render.cjs` にも効く）
- `VISUAL_VIEW=3,-2,1.6,0.6,0.4,0.2` … 視点を 1 つに決める（カメラの x,y,z と見る点の x,y,z）。気になる所に寄って見るとき
- `VISUAL_REPORT=all` … 出力のフォルダ名（既定は `report`）
- `VISUAL_CASES=別の一覧.tsv` … `render.cjs` で、`cases.tsv` の代わりに使う式の一覧

## 中身

- `cases.tsv` … 比べる式（名前・壁の有無と設定・式）。設定で、回転角・再生中の軽い計算（`flags=1`）・細かさを指定できる。
  `core/tests/shape.rs` の一覧と、アプリのサンプルの曲面
- `core/examples/dump_meshes.rs` … 式からメッシュを作って書き出す。表示範囲と細かさはアプリの既定と同じ。
  古いコミットにはこのファイルが無いので、`dump_revs.sh` が今の版をコピーして使う（`git worktree` の中で。元の作業ツリーは変えない）
- `render.cjs` … three.js（`web/node_modules`）と Playwright の Chromium で描く。法線は描画側で三角形ごとに作り直す
  （コミットごとの法線の違いではなく、形の違いを見る）。青緑が表、橙が裏。表示範囲の箱の外はアプリと同じく切り落とす

## 見方

「変化」は隣のコミットとの、色が大きく違う画素の割合（%）。変わった式を見つけるためのもので、良し悪しは画像を見て人が決める。
変化が 0 の式は、そのコミットで描画が変わっていない。
